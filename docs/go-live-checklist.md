# PD Monitor — สิ่งที่ต้องทำก่อนเปิดใช้งานจริง (สำหรับผู้บริหาร)

> จัดทำ 1 ต.ค. 2569 · ราคาและเงื่อนไขอ้างอิงหน้าเว็บทางการของ Vercel และ Supabase ณ วันที่จัดทำ (อาจเปลี่ยนได้)
> อัตราแลกเปลี่ยนในเอกสารนี้ใช้ประมาณ 1 USD ≈ 35 บาท

## สรุปสั้น ๆ

ตอนนี้ระบบใช้ **บริการฟรีทั้ง 2 ตัว** (Vercel = ตัวเว็บ · Supabase = ฐานข้อมูล) ซึ่งเหมาะกับ **ช่วงทดสอบ** แต่ **ไม่เหมาะกับการใช้งานจริง** ด้วยเหตุผลหลัก 3 ข้อ:

1. **Vercel แบบฟรีจำกัดไว้สำหรับ "ใช้ส่วนตัว ไม่ใช่เชิงพาณิชย์"** — ระบบนี้ใช้ภายใน ไม่ได้ขายของหรือเก็บเงินใคร
   แต่นิยามของ Vercel กว้างกว่าที่คิด: นับรวม "งานที่มีพนักงานหรือผู้รับจ้างที่ได้รับค่าจ้างเป็นคนเขียนโค้ด" ด้วย
   → **ควรส่งคำถามยืนยันกับ Vercel Support** ว่าระบบภายในของบริษัทใช้แพ็กเกจฟรีได้ไหม (ถ้าไม่ได้ = เสี่ยงถูกระงับเว็บ)
2. **Supabase แบบฟรีไม่มีการสำรองข้อมูล (backup)** — ถ้าข้อมูลเสียหายหรือถูกลบผิด **กู้คืนไม่ได้** ซึ่งข้อมูลการผลิต/ผลตรวจ/ลายเซ็นเป็นเอกสาร GMP
3. **Supabase แบบฟรีถูกพักอัตโนมัติถ้าไม่มีคนใช้ 7 วัน** — เช่น ช่วงหยุดยาวสงกรานต์/ปีใหม่ กลับมาแล้วระบบเข้าไม่ได้จนกว่าจะมีคนไปกดเปิด

**ค่าใช้จ่ายที่แนะนำ:**
- **ขั้นต่ำที่ควรมี: Supabase Pro $25/เดือน ≈ 900 บาท** (backup + ไม่ถูกพัก)
- **ถ้า Vercel ยืนยันว่าต้องใช้ Pro: รวม $45/เดือน ≈ 1,600 บาท**

## 1. Vercel (ตัวเว็บ) — ฟรี (Hobby) เทียบ Pro

| เรื่อง | ฟรี (Hobby) — ตอนนี้ | Pro ($20/เดือน ต่อนักพัฒนา 1 คน) |
|---|---|---|
| **การใช้เชิงพาณิชย์** | ⚠️ "ส่วนตัว ไม่ใช่เชิงพาณิชย์เท่านั้น" — ระบบภายในบริษัทเข้าข่ายหรือไม่ ควรถาม Vercel | ✅ อนุญาตทุกกรณี |
| ปริมาณการใช้งาน | มีเพดานตายตัว เกินแล้ว **ซื้อเพิ่มไม่ได้** (เว็บหยุด) | มีเครดิต $20/เดือน เกินจ่ายตามใช้ |
| เก็บ log ย้อนหลัง (ไว้ไล่ปัญหา) | 1 ชั่วโมง | 1 วัน |
| จำนวนคนดูแลระบบ | 1 คน | เพิ่มได้ ($20/คน) |

ℹ️ พนักงาน ~30 คนที่ "ใช้งาน" ระบบ **ไม่ต้องจ่ายรายหัว** — จ่ายเฉพาะคนที่ดูแล/แก้โค้ด

## 2. Supabase (ฐานข้อมูล) — ฟรี เทียบ Pro

| เรื่อง | ฟรี — ตอนนี้ | Pro ($25/เดือน) |
|---|---|---|
| **สำรองข้อมูล (backup)** | ❌ **ไม่มี** | ✅ อัตโนมัติทุกวัน เก็บย้อนหลัง 7 วัน |
| **พักโปรเจคเมื่อไม่มีคนใช้** | ⚠️ **พักอัตโนมัติหลัง 7 วัน** | ✅ ไม่พัก |
| ขนาดฐานข้อมูล | 500 MB | 8 GB (เกินคิด $0.125/GB) |
| ข้อมูลรับส่ง (egress) | 5 GB/เดือน | 250 GB/เดือน |
| กันรหัสผ่านที่เคยหลุดในเว็บอื่น | ❌ | ✅ |
| เก็บ log ย้อนหลัง | 1 วัน | 7 วัน |
| ช่องทางขอความช่วยเหลือ | ชุมชนออนไลน์ | อีเมลถึงทีม Supabase |

**ตัวเลือกเสริม — ย้อนเวลาข้อมูลได้ละเอียดรายวินาที (Point-in-Time Recovery):** +$100/เดือน (≈ 3,500 บาท)
→ แนะนำพิจารณาถ้าฝ่าย QA ต้องการให้กู้ข้อมูลถึงจุดเวลาที่ต้องการได้ (backup รายวันอาจเสียข้อมูลสูงสุด 1 วัน)

## 4. รายการที่ต้องทำก่อนเปิดใช้จริง

### 🔴 ต้องทำ (ก่อนวันเปิดใช้)
- [ ] **อนุมัติงบ + อัปเกรด Supabase Pro** ($25 ≈ 900 บาท/เดือน) — เรื่อง backup + ไม่ถูกพัก **สำคัญที่สุด**
- [ ] **Vercel Pro** ($20 ≈ 700 บาท/เดือน) — ขึ้นกับคำตอบของ Vercel Support เรื่องการใช้ภายในบริษัท
- [ ] **ทดสอบรอบ 2 ให้ผ่าน** ตามเช็กลิสต์ใน Notion และแก้สิ่งที่ทีมพบ
- [ ] **ล้างข้อมูลสมมติทั้งหมด** (งาน · บันทึก · ผลตรวจ) + รีเซ็ตเลขงาน + ลบบัญชีทดสอบ
- [ ] **สร้างบัญชีพนักงานจริงทุกคน** ด้วยอีเมลจริง และกำหนดสิทธิ์ (role) ให้ถูกฝ่าย — โดยเฉพาะ **หัวหน้า QC / หัวหน้า QA / หัวหน้าฝ่ายผลิต** ซึ่งเป็นผู้ลงนาม
- [ ] **ทุกคนตั้งรหัสผ่านของตัวเอง** (ระบบบังคับอยู่แล้ว) + ชี้แจงว่า **ห้ามใช้บัญชีร่วมกัน / ห้ามบอกรหัสคนอื่น** เพราะการบันทึกในระบบ = ลายเซ็นของคนนั้น
- [ ] **แจกคู่มือ + อบรมแต่ละฝ่าย** (มีคู่มือ PDF แล้ว: `docs/pd-monitor-manual.pdf`)
- [ ] **ตกลงวันเริ่มใช้** และกติกาช่วงเปลี่ยนผ่าน (จะจดกระดาษคู่ขนานกี่สัปดาห์)

### 🟠 ควรทำ (เกี่ยวกับมาตรฐาน GMP)
- [ ] **ให้ QA พิจารณาเรื่องการตรวจรับรองระบบคอมพิวเตอร์ (Computer System Validation)** — ระบบที่เก็บบันทึกการผลิต/ผลตรวจ/ลายเซ็นแทนกระดาษ ตามแนว GMP (PIC/S Annex 11) โดยทั่วไปต้องมีเอกสารยืนยันว่าระบบทำงานถูกต้องก่อนใช้แทนกระดาษ — ขอบเขตแค่ไหนให้ QA ของบริษัทเป็นผู้กำหนด
- [ ] **เลือกว่าจะซื้อ Point-in-Time Recovery ไหม** (+$100/เดือน) — ให้ QA ร่วมตัดสินว่ายอมเสียข้อมูลได้สูงสุดกี่ชั่วโมง
- [ ] **กำหนดผู้รับผิดชอบระบบ** — ใครดูแลบัญชีผู้ใช้ · ใครติดต่อเมื่อระบบมีปัญหา · ใครถือบัญชี Vercel/Supabase/GitHub ของบริษัท
- [ ] **ย้ายบัญชี Vercel / Supabase / GitHub มาเป็นของบริษัท** (ไม่ผูกกับอีเมลส่วนตัวของคนใดคนหนึ่ง) — กันปัญหาเมื่อคนดูแลลาออก

### 🟢 ปรับปรุงภายหลังได้ (ไม่บล็อกการเปิดใช้)
- [ ] ยืนยันตัวตน 2 ชั้น (MFA) สำหรับผู้บริหาร/ผู้ดูแลระบบ — ต้องพัฒนาหน้าจอเพิ่ม
- [ ] เปลี่ยน "ลบงาน" เป็นสถานะ "ยกเลิก" (ข้อมูลไม่หาย ตรวจย้อนหลังได้)
- [ ] ยืนยันรหัสผ่านตอนลงนามที่ระดับฐานข้อมูล (ปิดช่องสำหรับผู้ใช้ที่มีความรู้ด้านเทคนิค)
- [ ] ใช้ชื่อโดเมนของบริษัท (เช่น `pd.ชื่อบริษัท.com`) แทน `pd-monitor.vercel.app`

| ระบบมีปัญหาแล้วต้องไล่สาเหตุ | log เก็บแค่ 1 ชั่วโมง (Vercel) / 1 วัน (Supabase) มักหาสาเหตุไม่ทัน |

## 1.3 สิทธิ์ (role) 15 แบบ

คนหนึ่งถือได้หลายสิทธิ์พร้อมกัน

| สิทธิ์ | ตัวย่อ | หน้าที่หลัก |
|---|---|---|
| ฝ่ายวางแผน | PLN | วางแผนการผลิต — เปิดงานเข้าระบบ |
| หัวหน้าฝ่ายวางแผน | PLN-L | + ดูแลบัญชีทีมวางแผน |
| ฝ่ายผลิต | PROD | ผลิตจริงหน้างาน — บันทึกผลผลิตรายวัน |
| หัวหน้าฝ่ายผลิต | PROD-L | + ยืนยัน Line Clearance · อนุมัติบันทึกผลผลิต |
| QC | QC | ตรวจคุณภาพระหว่างผลิต + ตัดสิน QC |
| หัวหน้า QC | QC-L | + อนุมัติผลตรวจ in-process |
| QA | QA | ปล่อยผ่านล็อต + ดูแลเอกสารคุณภาพ |
| หัวหน้า QA | QA-L | + ดูแลบัญชีทีม QA |
| คลังสินค้า | WH | คลังผลิตภัณฑ์ + รับสินค้าสำเร็จรูปเข้าคลัง |
| หัวหน้าคลังสินค้า | WH-L | + ดูแลบัญชีทีมคลัง |
| วิศวกรรม | ENG | ดูแลเครื่องจักร — ซ่อมบำรุง / สอบเทียบ |
| หัวหน้าฝ่ายวิศวกรรม | ENG-L | + ดูแลบัญชีทีมวิศวกรรม |
| บัญชีต้นทุน | COST | ดูต้นทุนค่าแรงทางตรง |
| ผู้บริหาร | MGR | ดูภาพรวมและอนุมัติงานส่วนใหญ่ |
| ผู้ดูแลระบบ | ADM | ผ่านทุกสิทธิ์ |

**กติกาสืบทอด 2 ข้อ**

1. **ผู้ดูแลระบบ (admin) ผ่านทุกสิทธิ์เสมอ**
2. **หัวหน้าฝ่ายมีสิทธิ์ของลูกน้องในฝ่ายตัวเองด้วย** — แต่ **ทางเดียวเท่านั้น**
   หัวหน้าฝ่ายผลิต ⊃ ฝ่ายผลิต · แต่ฝ่ายผลิตไม่ได้สิทธิ์ของหัวหน้า

> 🔒 **นี่คือเหตุผลที่กฎ 2 ลายเซ็นทำงานได้** — ถ้าพนักงานได้สิทธิ์หัวหน้าด้วย ก็จะรับรองงานตัวเองได้
> ระบบจึงออกแบบให้สืบทอดทางเดียว

> ⚠️ **ผู้บริหารทำแทนได้เกือบทุกอย่าง ยกเว้นลงนาม QC/QA** — ระบบบังคับว่าผู้ลงนามปล่อยผ่าน
> ต้องถือสิทธิ์ QC หรือ QA จริง ตามแนว GMP

## 1.4 สถานะงาน 6 ขั้น

| # | สถานะ | ความหมาย | ใครเลื่อนไปขั้นต่อไป |
|:---:|---|---|---|
| 1 | **รอแจ้งผลิต** | เปิดงานแล้ว ยังไม่ยืนยันแผน | ฝ่ายวางแผน · ผู้บริหาร |
| 2 | **มีแผนแล้ว** | ยืนยันแผนแล้ว รอเริ่มผลิต | ฝ่ายผลิต · ผู้บริหาร |
| 3 | **กำลังผลิต** | ผลิตอยู่ · บันทึกผลผลิตได้เฉพาะตอนนี้ | **ฝ่ายผลิตเท่านั้น** |
| 4 | **QC** | รอ QC ตัดสิน | **QC เท่านั้น** (ต้องลงนาม) |
| 5 | **QA** | รอ QA ปล่อยผ่าน | **QA เท่านั้น** (ต้องลงนาม) |
| 6 | **FG (เข้าคลัง)** | ปิดงาน — หายจากบอร์ด | — |

**ถอยหลังได้ทางเดียว: ตีกลับ** — QC หรือ QA ตีกลับ งานจะกลับไป **"กำลังผลิต"** และต้องระบุเหตุผล

**ป้ายปัญหา** (แยกจากสถานะ · ตั้งได้ทุกเมื่อ): 🔴 ติดปัญหา · 🟡 รอแก้ไข · 🟠 ล่าช้า

### "Status" ต่างจาก "สถานะ" อย่างไร

| | **สถานะ** (6 ขั้นข้างบน) | **Status** (ช่องในการ์ดข้อมูลงาน) |
|---|---|---|
| ใครกำหนด | ระบบบังคับ | ทีมพิมพ์/เลือกเอง |
| ตัวอย่าง | กำลังผลิต · QC | `ไม่มีแผน` · `มีแผน08/26` · `รอวัตถุดิบ` |
| มีผลกับด่าน GMP | **ใช่** | **ไม่** |
| ใช้ทำอะไร | คุมลำดับงานจริง | สื่อสารกันในทีม · กรองในตารางพิมพ์ |

> 💡 **Status บางค่าจะขอ "เดือนแผน" ด้วย** — เลือกแล้วบนบอร์ดจะแสดงเป็น `มีแผน08/26`
> (เดือน/ปี ค.ศ. 2 หลัก)

## 1.5 แดชบอร์ด

📍 หน้าแรกหลังล็อกอิน

**บล็อก Pending Order = Plan + WIP** — งานที่ยังไม่เข้าคลังทั้งหมด

| กลุ่ม | การ์ด | หมายถึง |
|---|---|---|
| **Plan** | ยังไม่ลงแผน | สถานะ "รอแจ้งผลิต" และ Status ยังไม่มีแผน |
| | รอแจ้งผลิต | ลงแผนแล้ว รอประกาศ |
| | มีแผนแล้ว | สถานะ "มีแผนแล้ว" |
| **WIP** | ผลิต | กำลังผลิต · ยังไม่ถึงสถานีบรรจุ |
| | แพ็ค | บันทึกผลผลิตล่าสุดอยู่ที่สถานีที่ติ๊ก "แพ็ค" |
| | QC · QA | ตามสถานะ |
| | รอเข้าคลัง | QA ปล่อยผ่านแล้ว คลังยังไม่รับเข้า |

🖱️ กดการ์ดใดก็ได้ → กระโดดไปบอร์ดงานที่กรองไว้แล้ว

## 2.3 หน้ารายละเอียดงาน

**เข้าจาก** กดการ์ดงานบนบอร์ด · **ใครเข้าได้** ทุกคน (ปุ่มต่างกันตามสิทธิ์)

หน้านี้คือศูนย์กลางของงาน 1 ใบ เรียงจากบนลงล่างตามลำดับการใช้จริง

| # | ส่วน | ใครใช้ |
|:---:|---|---|
| 1 | ปุ่ม "← กลับบอร์ดงาน" · **"📄 ดู eBR"** | ทุกคน |
| 2 | เลขงาน + ป้ายบริษัท + ป้ายสถานะ + ป้ายปัญหา | — |
| 3 | **แถบสถานะ 6 ขั้น** | — |
| 4 | **การ์ดข้อมูลงาน** + ปุ่ม "✏️ แก้ไขข้อมูล" | แก้ได้ตามฝ่าย |
| 5 | **ดำเนินการ** — ปุ่มเลื่อนสถานะ + แผงลงนาม + ปุ่ม "🗑️ ลบงานนี้" | ตามสถานะ/สิทธิ์ |
| 6 | **เบิกวัตถุดิบ/บรรจุภัณฑ์** | ผลิตลงรายการ · คลังกดพร้อม |
| 7 | **แท็บขั้นตอนการผลิต** | ทุกคน |
| 8 | **เครื่องจักรของขั้นตอนนี้** | ผลิต · ผู้บริหาร |
| 9 | **Line Clearance** | ผลิตทำ · หัวหน้ายืนยัน |
| 10 | **บันทึกผลผลิตรายวัน** + แถบอนุมัติหลายรายการ | ผลิตบันทึก · หัวหน้าอนุมัติ |
| 11 | **ตรวจระหว่างผลิต (In-process QC)** | QC ลงผล · หัวหน้า QC อนุมัติ |
| 12 | **จุดเก็บตัวอย่าง (ตรวจ Finished product)** | QA |
| 13 | **⚠️ Incident Case** | ทุกคนเปิดได้ · QA ตัดสิน |
| 14 | **ประวัติการแก้ไขย้อนหลัง** | ทุกคนดูได้ |
| 15 | **ลายเซ็นอนุมัติคุณภาพ (QC / QA)** | ทุกคนดูได้ |

**แถบเตือนที่อาจขึ้นด้านบน**

| แถบ | แปลว่า | แก้ยังไง |
|---|---|---|
| ไม่มีขั้นตอนการผลิต | ยาตัวนี้ยังไม่ได้ตั้ง Route | ผู้บริหารไปตั้งที่หน้าผลิตภัณฑ์ |
| ยังไม่มีเลขล็อต | ยังไม่ได้กรอก LOT No. | ฝ่ายผลิตกรอกในการ์ดข้อมูลงาน |

**สิทธิ์ราย field ในการ์ดข้อมูลงาน**

| ช่อง | ฝ่ายที่แก้ได้ | ล็อกเมื่อสถานะถึง |
|---|---|---|
| Status · เดือนแผน · หมายเหตุ | วางแผน + ผลิต | ไม่ล็อก |
| กำหนดส่ง | วางแผน | ไม่ล็อก |
| ลูกค้า · C.P.O DATE | วางแผน | FG |
| ใบคำขอ | วางแผน + ผลิต | FG |
| แผนเริ่ม · แผนเสร็จ | ผลิต | FG |
| Batch Size · รูปแบบบรรจุ · Pack Size (1)(2)(3) | วางแผน | **กำลังผลิต** |
| LOT No. (Batch NO.) | ผลิต | ไม่ล็อก |
| วันผลิต · วันหมดอายุ | วางแผน + ผลิต (ต้องมีเลขล็อตก่อน) | ไม่ล็อก |

> 🔒 **ช่องที่ล็อกแล้วยังแก้ได้ถ้าระบุเหตุผล** — เหตุผลถูกเก็บลงประวัติ / Audit

> ⚠️ **Job No. · รหัสยา · REG NO. · ลักษณะยา แก้ที่หน้านี้ไม่ได้**

> 💡 **A4 หนึ่งแผ่น = 2 Job** มีเส้นประกลางไว้ฉีก · ช่อง LOT NO. / MFG. DATE / EXP.DATE เว้นไว้เขียนมือ

> 💡 **ถ้าเนื้อหายาวเกินครึ่งแผ่น ระบบย่อให้อัตโนมัติ** (ต่ำสุด 60%) และเตือนพร้อมเลขงานถ้ายังถูกตัด

## 2.6 ปริ้นตารางบอร์ดงาน (F.PLN.10) + Excel

|---|---|---|
| ผู้บริหาร · ผู้ดูแลระบบ | ทุกคน | ทุกสิทธิ์ |
| หัวหน้าแผนก | **เฉพาะพนักงานในฝ่ายตัวเอง** | **เฉพาะสิทธิ์ของฝ่ายตัวเอง** |

> 💡 **บัญชีใหม่ถูกบังคับให้ตั้งรหัสผ่านเองตอนล็อกอินครั้งแรก**

> ⚠️ **ลบบัญชีที่เคยทำงานแล้ว = ปิดล็อกอิน + ล้างสิทธิ์ + ปลดอีเมล + ซ่อนชื่อ** —
> ประวัติและลายเซ็นยังอยู่ครบตาม GMP

> ⚠️ **ระงับหรือลบบัญชีตัวเองไม่ได้**

# 3 · กติกา GMP ที่ระบบบังคับ

หัวข้อนี้อธิบาย "ทำไมระบบถึงไม่ยอมให้กด" — ทุกข้อบังคับที่ **ฐานข้อมูล** ไม่ใช่แค่ซ่อนปุ่มบนหน้าจอ
ต่อให้เรียกตรงเข้าระบบก็ยังผ่านไม่ได้

---

## 3.1 กฎสองลายเซ็น — 5 ชุด

**คนทำกับคนรับรองต้องเป็นคนละคน** ทุกชุด

| ชุด | ผู้ทำ | ผู้รับรอง | ถ้าเป็นคนเดียวกันจะเจอ |
|---|---|---|---|
| **Line Clearance** | ฝ่ายผลิต | หัวหน้าฝ่ายผลิต · ผู้บริหาร | "ผู้ยืนยันต้องเป็นคนละคนกับผู้ทำ" |
| **บันทึกผลผลิตรายวัน** | ฝ่ายผลิต | หัวหน้าฝ่ายผลิต · ผู้บริหาร | "ผู้อนุมัติต้องเป็นคนละคนกับผู้บันทึก" |
| **ผลตรวจ In-process** | QC | หัวหน้า QC · ผู้บริหาร | "ผู้อนุมัติต้องเป็นคนละคนกับผู้ลงผล" |
| **ลงนาม QC / QA** | — | **QC / QA ตัวจริงเท่านั้น** | ปุ่มไม่ขึ้นให้เลย |
| **คำขอแก้ไขย้อนหลัง** | ทุกคนที่ล็อกอิน | ผู้บริหาร · หัวหน้าฝ่ายที่เกี่ยว | — |

> 💡 **แถบอนุมัติหลายรายการ** ของบันทึกผลผลิต จะ **ข้ามบันทึกของตัวเองให้อัตโนมัติ**
> แล้วรายงานว่าข้ามไปกี่รายการ ไม่ต้องมานั่งติ๊กออกทีละแถว

---

## 3.2 ด่านกั้นที่กดข้ามไม่ได้

| ด่าน | เงื่อนไข | ถ้าไม่ผ่านจะเจอ |
|---|---|---|
| **เริ่มผลิต** | ต้องมี **LOT No.** ก่อน | แถบเตือนสีเหลือง "ยังไม่มีเลขล็อต" |
| **บันทึกผลผลิต** | สถานะต้องเป็น **"กำลังผลิต"** เท่านั้น | ไม่มีปุ่มบันทึก |
| **บันทึกผลผลิต** | ผลิตภัณฑ์ต้องมี **Route** | แถบเตือนสีแดง "ไม่มีขั้นตอนการผลิต" |
| **ส่งตรวจ QC** | ต้องตรวจ in-process ครบทุกสถานีใน Route และ **หัวหน้า QC อนุมัติแล้ว** | แถบความคืบหน้า QC ยังไม่เต็ม |
| **ส่งตรวจ QC** | ต้องเป็น **ฝ่ายผลิต** เท่านั้น | ผู้บริหารไม่เห็นปุ่ม |
| **QA ปล่อยผ่าน → FG** | ต้องไม่มี **Incident Case ค้าง** | กดไม่ผ่าน |
| **ลงนาม QC / QA** | ต้องยืนยัน **รหัสผ่านของตัวเอง** | ลงนามไม่สำเร็จ |
| **Line Clearance** | ต้องติ๊กอย่างน้อย 1 ข้อ | ยืนยันไม่ได้ |
| **เลือกเครื่องจักรให้ขั้นตอน** | เครื่องต้องอยู่ **สถานีเดียวกับขั้นตอน** | ไม่ขึ้นในรายการให้เลือก |
| **บันทึกผลผลิต** | เครื่องที่ **ซ่อมบำรุง / ถึงกำหนดสอบเทียบ** จะไม่ขึ้นให้เลือก | — |

---

## 3.3 ประวัติที่ลบไม่ได้ (Audit trail)

- ทุกการ **เพิ่ม / แก้ไข / ลบ** ถูกบันทึกพร้อม **ใคร · เมื่อไร · ค่าเดิม → ค่าใหม่**
- **แก้ไม่ได้ ลบไม่ได้** แม้แต่ผู้ดูแลระบบ
- **ลบบัญชีที่เคยทำงานแล้ว ไม่ลบประวัติทิ้ง** — ระบบปิดล็อกอิน ล้างสิทธิ์ ปลดอีเมล แล้วซ่อนชื่อแทน
- **การแก้ช่องที่ถูกล็อก** ต้องระบุเหตุผล และเหตุผลนั้นถูกเก็บไว้ในประวัติด้วย
- **การลบจุดเก็บตัวอย่าง** ต้องระบุเหตุผล
- **การยกเลิก / ปิดข้ามขั้น Incident Case** ต้องระบุเหตุผล และเหตุผลไปอยู่ใน timeline ของเคส

---

## 3.4 คำขอแก้ไขย้อนหลัง (Amendment)

ข้อมูล 2 ชนิดที่แก้เองไม่ได้ ต้องขออนุมัติ

| ชนิด | ผู้ยื่น | ผู้อนุมัติ |
|---|---|---|
| **บันทึกผลผลิต** | ผู้บันทึก | ผู้บริหาร · หัวหน้าฝ่ายผลิต |
| **ผลตรวจ QC ระหว่างผลิต** | QC (ฝ่ายอื่นยื่นไม่ได้) | ผู้บริหาร · หัวหน้า QC |

**ขั้นตอน** — กด "✏️ ขอแก้ไข" ที่แถวนั้น → แก้ค่า + **ระบุเหตุผล** → ส่งคำขอ →
ผู้อนุมัติเห็นในเมนู "คำขอแก้ไข" พร้อม diff ค่าเดิม/ค่าใหม่ → อนุมัติ (ระบบแก้ให้เลย) หรือปฏิเสธ (ต้องใส่หมายเหตุ)
→ **ผลส่งกลับถึงผู้ยื่นคนเดียว**

> ⚠️ **แก้บันทึกผลผลิตที่อนุมัติไปแล้ว = แถวเด้งกลับเป็น "รออนุมัติ" ใหม่** และหัวหน้าได้แจ้งเตือนอีกครั้ง

---

# 4 · สรุปรายฝ่าย

หน้าในหัวข้อนี้ออกแบบให้ **ฉีกไปแปะข้างเครื่อง / ติดบอร์ดของแผนก** ได้เลย

---

## 4.1 ฝ่ายวางแผน (PLN / PLN-L)

**หน้าที่หลัก** วางแผนการผลิต — เปิดงานเข้าระบบ

**บันทึก / แก้ไขได้**
- สร้างงานผลิตใหม่ทีละหลายใบ (ออเดอร์ + งาน · เลขล็อตเป็นของฝ่ายผลิต)
- เพิ่ม / แก้ / ลบผลิตภัณฑ์ในทะเบียน
- ตั้งสถานะล็อตในคลัง (พร้อมใช้ / ไม่พร้อมใช้)
- ยืนยันแผนผลิต (รอแจ้งผลิต → มีแผนแล้ว)
- ปริ้นใบแจ้งผลิต F.PLN.01
- แก้ข้อมูลงานฝั่งวางแผน — ลูกค้า · C.P.O DATE · กำหนดส่ง · Batch Size · รูปแบบ/ขนาดบรรจุ

**หัวหน้าฝ่ายวางแผนได้เพิ่ม** สร้าง / ดูแล / ลบบัญชีพนักงานในฝ่ายวางแผน

**ทำไม่ได้** กรอก LOT No. · ทำ Line Clearance · บันทึกผลผลิต · ลงนาม QC/QA

---

## 4.2 ฝ่ายผลิต (PROD / PROD-L)

**หน้าที่หลัก** ผลิตจริงหน้างาน — บันทึกผลผลิตรายวัน

**บันทึก / แก้ไขได้**
- กรอก LOT No. ให้งาน (ก่อนเริ่มผลิต)
- ทำ Line Clearance (ผู้ปฏิบัติ) → เริ่มผลิต
- บันทึกผลผลิตรายสถานี (กะ · ช่วงเวลา/OT · เครื่องจักร · ยอด · ของเสีย · นาที · จำนวนคน)
- ลงรายการวัตถุดิบ/บรรจุภัณฑ์ที่ต้องเบิก **(กดสถานะพร้อมไม่ได้)**
- ผูก / ถอดเครื่องจักรกับขั้นตอนการผลิตของงาน
- **ส่งตรวจ QC** (ขั้นนี้ฝ่ายผลิตเท่านั้น)
- เพิ่ม / แก้ทะเบียนเครื่องจักร (ยกเว้นกำหนดซ่อม / สอบเทียบ)
- เปิด Incident Case · ขออนุมัติแก้ไขย้อนหลัง

**หัวหน้าฝ่ายผลิตได้เพิ่ม**
- **ยืนยัน Line Clearance** ที่พนักงานติ๊กไว้ (ต้องคนละคนกับผู้ทำ)
- **อนุมัติ / ไม่อนุมัติบันทึกผลผลิต** (ต้องคนละคนกับผู้บันทึก)
- **อนุมัติคำขอแก้ไขบันทึกผลผลิตย้อนหลัง**
- สร้าง / ดูแล / ลบบัญชีพนักงานในฝ่ายผลิต

**ทำไม่ได้** กดสถานะความพร้อมของรายการเบิก (เป็นของคลัง) · ลงนาม QC/QA

---

## 4.3 QC (QC / QC-L)

**หน้าที่หลัก** ตรวจคุณภาพระหว่างผลิต + ตัดสิน QC

**บันทึก / แก้ไขได้**
- บันทึกผลตรวจ in-process QC รายสถานี (หัวข้อ · ค่า · ผล · Valid date)
- **QC ผ่าน → ส่ง QA** และ **QC ตีกลับ** (ต้องลงนามด้วยรหัสผ่าน)
- เปิด Incident Case
- ขอแก้ไขผลตรวจ in-process ย้อนหลัง (ฝ่ายอื่นขอไม่ได้)

**หัวหน้า QC ได้เพิ่ม**
- **อนุมัติ / ไม่อนุมัติผลตรวจ in-process** ที่ QC ลงไว้
- **อนุมัติคำขอแก้ไขผลตรวจ in-process**
- สร้าง / ดูแล / ลบบัญชีพนักงานในฝ่าย QC

**เห็นเพิ่ม** หน้าตรวจ QC / QA

---

## 4.4 QA (QA / QA-L)

**หน้าที่หลัก** ปล่อยผ่านล็อต + ดูแลเอกสารคุณภาพ

**บันทึก / แก้ไขได้**
- บันทึก / แก้ไข / ลบ จุดเก็บตัวอย่าง (ตรวจ Finished product) — ลบต้องระบุเหตุผล
- **QA ปล่อยผ่าน → FG** และ **QA ตีกลับ** (ต้องลงนามด้วยรหัสผ่าน)
- **ตรวจสอบ Incident Case** — ระบุประเภท DEV / OOS / NC + เลขที่เอกสาร + แผนกที่รับผิดชอบ (หลายแผนกได้)
  แล้วอนุมัติปิดเคส หรือส่งกลับให้แผนกแก้ใหม่

**หัวหน้า QA ได้เพิ่ม** สร้าง / ดูแล / ลบบัญชีพนักงานในฝ่าย QA

**เห็นเพิ่ม** ประวัติ / Audit · ไล่ย้อนล็อต (Trace) · คำขอแก้ไข (ดูได้ ไม่ใช่ผู้อนุมัติ)

> 🔑 **QA ไม่ได้เป็นผู้อนุมัติคำขอแก้ไขแล้ว** — คำขอแก้ผลตรวจ in-process เป็นเรื่องภายในของฝ่าย QC

---

## 4.5 คลังสินค้า (WH / WH-L)

**หน้าที่หลัก** คลังผลิตภัณฑ์ + รับสินค้าสำเร็จรูปเข้าคลัง

**บันทึก / แก้ไขได้**
- เพิ่ม / แก้ / ลบผลิตภัณฑ์ในทะเบียน (แก้ขั้นตอนการผลิตไม่ได้)
- ล็อต / สต็อกของผลิตภัณฑ์ทุกตัว
- **กดสถานะ พร้อม / ไม่พร้อม ให้รายการเบิกของแต่ละงาน** (เพิ่ม/แก้/ลบรายการไม่ได้)
- **รับ FG เข้าคลัง** = ปิดงาน

**หัวหน้าคลังได้เพิ่ม** สร้าง / ดูแล / ลบบัญชีพนักงานในฝ่ายคลัง

**เห็นเพิ่ม** คลัง / FG · เบิกวัตถุดิบ / บรรจุภัณฑ์ · ไล่ย้อนล็อต (Trace)

> ⚠️ **ตั้งสถานะล็อตไม่ได้** — เป็นของฝ่ายวางแผน

---

## 4.6 วิศวกรรม (ENG / ENG-L)

**หน้าที่หลัก** ดูแลเครื่องจักร — ซ่อมบำรุง / สอบเทียบ

**บันทึก / แก้ไขได้**
- เพิ่ม / แก้ทะเบียนเครื่องจักร (รวมห้อง · สถานะ)
- **กำหนดวันซ่อมบำรุง + วันสอบเทียบครั้งหน้า** (ฝ่ายผลิตทำข้อนี้ไม่ได้)
- บันทึกหมายเหตุ Incident Case ในนามฝ่ายวิศวกรรม

**หัวหน้าฝ่ายวิศวกรรมได้เพิ่ม** สร้าง / ดูแล / ลบบัญชีพนักงานในฝ่ายวิศวกรรม

**เห็นเพิ่ม** รายงานการใช้เครื่อง

---

## 4.7 บัญชีต้นทุน (COST)

**หน้าที่หลัก** ดูต้นทุนค่าแรงทางตรง

**บันทึก / แก้ไขได้** ปรับอัตราค่าแรง (฿/ชม.) ที่ใช้คำนวณบนแดชบอร์ด

**เห็นเพิ่ม** ต้นทุนค่าแรงทางตรง (DL cost) รวม + แยกรายสถานี · คน-ชั่วโมงและชั่วโมงทำงานตามช่วงวันที่

---

## 4.8 ผู้บริหาร (MGR) และผู้ดูแลระบบ (ADM)

**ผู้บริหาร — ทำแทนได้เกือบทุกอย่าง**
- สร้างงาน / ยืนยันแผน / เริ่มผลิต / เครื่องจักร / ผลิตภัณฑ์
- **ยืนยัน Line Clearance · อนุมัติบันทึกผลผลิต · อนุมัติผลตรวจ in-process** (แทนหัวหน้าฝ่ายได้)
- จัดการผู้ใช้ + กำหนดสิทธิ์ · รีเซ็ตรหัสผ่าน · ระงับ / ลบบัญชี
- สถานีการผลิต (master) + ขั้นตอนการผลิต (Route) ของแต่ละผลิตภัณฑ์
- ตั้งบริษัท / เลขงาน · อนุมัติคำขอแก้ไขย้อนหลังทุกชนิด · ลบงาน
- เห็นแจ้งเตือนของทุกฝ่าย (ยกเว้นใบที่จ่าหน้าถึงตัวบุคคล)

> 🔒 **สิ่งเดียวที่ผู้บริหารทำไม่ได้: ลงนามขั้น QC / QA**
> ระบบบังคับว่าผู้ลงนามต้องถือสิทธิ์ QC หรือ QA จริง ตามแนว GMP ที่ผู้ปล่อยผ่านต้องเป็นผู้มีคุณสมบัติของฝ่ายนั้น

**ผู้ดูแลระบบ (Admin)** ผ่านทุกสิทธิ์ · เห็นทุกหน้าในระบบ

---

# 5 · ถาม–ตอบ และแก้ปัญหาที่พบบ่อย

**เข้าระบบไม่ได้ / ขึ้นว่าบัญชีถูกระงับ**
ติดต่อหัวหน้าแผนกหรือผู้ดูแลระบบให้เปิดใช้งานบัญชีหรือรีเซ็ตรหัสผ่านให้

**เห็นเมนูน้อยกว่าเพื่อน**
ปกติ — ระบบซ่อนเมนูที่ฝ่ายคุณไม่ได้ใช้ ถ้าคิดว่าควรเห็น ให้หัวหน้าตรวจสิทธิ์ในหน้าจัดการผู้ใช้

**กด "เริ่มผลิต" ไม่ได้**
ยังไม่ได้กรอก **LOT No.** — ฝ่ายผลิตกรอกที่การ์ดข้อมูลงาน

**ไม่มีปุ่ม "บันทึกผลผลิต"**
① สถานะงานยังไม่ใช่ "กำลังผลิต" หรือ ② ผลิตภัณฑ์ยังไม่มี **ขั้นตอนการผลิต (Route)** — ดูแถบเตือนด้านบนของหน้า

**เลือกเครื่องจักรที่ต้องการไม่เจอ**
เครื่องนั้นยังไม่ได้ผูกกับ **สถานี** ของขั้นตอนนี้ (ตั้งที่หน้าเครื่องจักร) ·
หรือเครื่องอยู่สถานะ **ซ่อมบำรุง / ถึงกำหนดสอบเทียบ**

**ยืนยัน Line Clearance เองไม่ได้**
ถูกต้องแล้ว — ผู้ยืนยันต้องเป็น **หัวหน้าฝ่ายผลิต** และต้องเป็นคนละคนกับผู้ทำ

**กด "ส่งตรวจ QC" ไม่ได้**
① ต้องเป็นบัญชี **ฝ่ายผลิต** (ผู้บริหารกดแทนไม่ได้) ② ผลตรวจ in-process ต้องครบทุกสถานีใน Route
**และหัวหน้า QC อนุมัติแล้ว** — ดูแถบความคืบหน้าในการ์ด In-process QC

**QA กด "ปล่อยผ่าน" ไม่ได้**
ยังมี **Incident Case ค้าง** อยู่ — ต้องปิดหรือยกเลิกเคสให้หมดก่อน

**ผู้บริหารกดลงนาม QC/QA แทนไม่ได้**
ถูกต้องแล้ว — ต้องเป็น QC หรือ QA ตัวจริงเท่านั้น ตามแนว GMP

**บันทึกผิด แก้เองไม่ได้**
ใช้ปุ่ม **"✏️ ขอแก้ไข"** ที่แถวนั้น แล้วให้ผู้มีสิทธิ์อนุมัติ (ดู §3.4)

**ตัวเลขบนกระดิ่งไม่ตรงกับที่เห็นในกล่อง**
ไม่ควรเกิดแล้ว · ถ้ายังเจอ ให้ลองรีเฟรชหนึ่งครั้ง — และจำไว้ว่า ⏰ เกินกำหนด กับ 🐢 ค้างนาน
**ไม่ถูกนับ** ในตัวเลขสีแดงโดยตั้งใจ

**แจ้งเตือนไม่หายสักที**
แจ้งเตือนชุดใหม่ต้องกด **"อ่านแล้ว"** เอง ไม่หายอัตโนมัติ

**งานหายจากบอร์ด**
งานที่รับเข้าคลัง (FG) แล้วจะถูกซ่อนออกจากบอร์ด — ยังค้นหาเจอและเปิด eBR ได้

**ปริ้นแล้วมีชื่อเรื่อง / เวลา / URL ติดมาบนกระดาษ**
เอาติ๊ก **"Headers and footers"** ออกในหน้าต่างพิมพ์ของเบราว์เซอร์

**ปริ้นแล้วขนาดไม่ตรงฟอร์มกระดาษ**
ตั้ง **Margins = Default** และ **Scale = 100%** ในหน้าต่างพิมพ์

**ค้นหาด้วยเลขล็อตวัตถุดิบใน Trace ไม่เจอ**
ทำไม่ได้แล้ว — ใช้ **เลขงาน** หรือ **เลขล็อตผลิต** แทน

**เน็ตหลุดตอนกดบันทึกผลผลิต**
ระบบเก็บไว้ในเครื่องแล้วส่งซ้ำให้เองเมื่อเน็ตกลับมา และกันไม่ให้เกิดแถวซ้ำ

> 📌 **ถ้าเจอปัญหาที่คู่มือนี้ไม่ครอบคลุม** — จดเลขงานและเวลาที่เกิด แล้วแจ้งผู้ดูแลระบบ
> ข้อความสีแดงที่ระบบขึ้นให้ตอนกดไม่ผ่านมักบอกสาเหตุไว้แล้ว ให้ถ่ายภาพหน้าจอส่งไปด้วย

## ข. คำศัพท์ที่ใช้ในระบบ

| คำ | หมายถึง |
|---|---|
| **Job No.** | เลขงานผลิต ระบบออกให้อัตโนมัติ แยกชุดตามบริษัท |
| **LOT No. / Batch NO.** | เลขล็อตผลิต — ฝ่ายผลิตกรอก ใช้ไล่ย้อนได้ |
| **Batch Size** | จำนวนที่สั่งผลิตของงานใบนั้น |
| **Route / ขั้นตอนการผลิต** | ลำดับสถานีที่ยาตัวนั้นต้องเดินผ่าน |
| **สถานี** | ขั้นตอนการผลิตหนึ่งขั้น เช่น ตอกเม็ด · เคลือบฟิล์ม · บรรจุ |
| **Line Clearance** | การเคลียร์และเตรียมสายการผลิตก่อนเริ่มงานใหม่ |
| **In-process QC** | การตรวจคุณภาพระหว่างผลิต แยกตามสถานี |
| **Finished product** | การตรวจสินค้าสำเร็จรูป — ในระบบอยู่ในการ์ด "จุดเก็บตัวอย่าง" |
| **Incident Case** | เหตุผิดปกติ (เดิมเรียก Deviation) — flow 5 ขั้น |
| **DEV / OOS / NC** | ประเภทเอกสารของ Incident Case ที่ QA เป็นผู้คัดแยก |
| **FG** | Finished Goods — สินค้าสำเร็จรูปที่รับเข้าคลังแล้ว |
| **eBR** | Electronic Batch Record — แฟ้มบันทึกการผลิตของงาน 1 ใบ |
| **Amendment** | คำขอแก้ไขข้อมูลย้อนหลัง |
| **Audit trail** | ประวัติการเปลี่ยนแปลงที่แก้ไม่ได้ ลบไม่ได้ |
| **Yield** | ผลิตได้ ÷ ยอดตั้งต้น |
| **WIP** | Work In Progress — งานที่เริ่มผลิตแล้วแต่ยังไม่เข้าคลัง |
| **C.P.O DATE** | วันที่ลูกค้าสั่งผลิต |
| **F.PLN.01 / F.PLN.10** | รหัสฟอร์มกระดาษ — ใบแจ้งผลิต / ตารางบอร์ดงาน |

## ค. สิ่งที่เปลี่ยนไปจากคู่มือฉบับก่อน (กรกฎาคม 2569)

ถ้าคุณเคยอ่านคู่มือชุดเดิม สิ่งเหล่านี้ **เปลี่ยนไปแล้ว**

**ของที่เอาออกจากระบบ**

| เดิมมี | ตอนนี้ |
|---|---|
| สูตรการผลิต / BOM | **ยกเลิกทั้งชุด** — ใช้ "ขั้นตอนการผลิต (Route)" แทน |
| ประเภทผลิตภัณฑ์ | ยกเลิก |
| กลุ่มหลัก | ยกเลิก — ใช้สถานีจริงอย่างเดียว |
| ใบเบิกที่ผูกกับล็อตในคลัง | เปลี่ยนเป็น **ลงรายการเบิกหน้างาน** ⇒ Trace ไล่ย้อนจากเลขล็อตวัตถุดิบไม่ได้แล้ว |
| Deviation (3 สถานะ) | เปลี่ยนเป็น **Incident Case (5 สถานะ)** + QA คัดประเภท DEV/OOS/NC |

**ของใหม่ที่คู่มือเดิมไม่มี**

- **ระบบแจ้งเตือนรายฝ่าย 13 ชนิด** + ชิปตัวกรอง + แจ้งเตือนรายบุคคล
- **ปริ้นใบแจ้งผลิต F.PLN.01** (UMEDA / POND) และ **ปริ้นตารางบอร์ดงาน F.PLN.10 + ออก Excel**
- **บริษัท UMEDA / POND** แยกชุดเลขงาน
- **สิทธิ์หัวหน้าแผนก 6 ฝ่าย** (รวมเป็น 15 สิทธิ์) + หัวหน้าดูแลบัญชีลูกน้องได้
- **การอนุมัติบันทึกผลผลิตโดยหัวหน้าฝ่ายผลิต** และ **การอนุมัติผลตรวจ in-process โดยหัวหน้า QC**
- **แดชบอร์ด Pending Order (Plan + WIP)**
- **แท็บขั้นตอนการผลิต** + **Line Clearance แยกตามขั้นตอน × เครื่อง**
- บันทึกผลผลิตแบบ **กะ / OT / นาที** และ **หน่วยแยกรายช่อง**
- **ลักษณะยา** ในทะเบียนผลิตภัณฑ์
- **ลบบัญชีผู้ใช้** · **ตั้ง Status ย่อย + เดือนแผน** ของงาน

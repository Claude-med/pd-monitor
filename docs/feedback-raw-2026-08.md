## 1. ⭐ ธีมใหญ่ที่สุด — ระบบต้อง "พูดภาษาโรงงาน" ไม่ใช่ภาษาแอป

ทุกฝ่ายเขียนตรงกันเรื่องเดียว: **ชื่อฟิลด์ · สถานะ · เอกสาร ต้องเป็นของจริงที่โรงงานใช้อยู่**
ไม่ใช่ศัพท์กลางๆ ที่ระบบตั้งเอง

### 1.1 เปลี่ยนชื่อฟิลด์ (B-p05 · C-p10 · B-p09)

| ตอนนี้ในแอป | ที่ทีมขอ | หมายเหตุ |
|---|---|---|
| รหัสยา (code) | **FORMULA NO.** | ตัวเลขสูตร |
| — (ไม่มี) | **REG NO.** | เลขทะเบียนตำรับยา (เช่น `1A 119/59`) — แทนช่อง "เวลามาตรฐาน (ชม.)" ที่ถูกขีดฆ่า |
| เลขงาน (Job No) | **JOB NO.** | + ต้องมี **BATCH NO.** แยกอีกช่อง ("มี 2 อัน") |
| จำนวน | **BATCH SIZE** | |
| — (ไม่มี) | **PACKING SIZE** | "เพราะบางยาใน 1 Lot มีรูปแบบการบรรจุหลายชนิด" → **สูงสุด 3 ขนาด** |
| เวลามาตรฐาน (ชม.) | *(ตัดทิ้ง)* | ขีดฆ่าทั้ง B และ C |

- **กำหนดส่ง**: จาก `+14 วัน` → **`+75 วัน`** นับจากวันที่สร้างงาน (B-p05, B-p06 "วันนี้ / +75 วัน")
- **แผนเริ่ม–แผนเสร็จ**: ขีดฆ่า → เปลี่ยนเป็น **"วันเปิดผลิต"** (B-p06 "ตัดออกจากวางแผน เป็นวันเปิดผลิต")
- **เลขล็อต**: ขีดฆ่าออกจากฟอร์มสร้างงาน → **ฝ่ายผลิตกรอกทีหลัง ก่อนกดเริ่มผลิต** (A-p07 "ฝ่ายผลิตออก" · B-p09 · B-p12 "ก่อนกดเริ่มผลิต วางแผนกรอก Batch No.")
- **รูปแบบวันที่**: `วว/ดด/YYYY` (B-p06)
- **ล็อกอินด้วย Username** ไม่ใช่อีเมล (C-p04)

### 1.2 ทุก dropdown ต้องมาจาก Database จริง (A-p01)

> *"มี Database ทุกอันนี้ ใช่ Excel เชื่อมด้วย Code"* · *"มี DataBase ทำเป็น Dropdown ด้วย **แต่ขอเพิ่มลูกค้าใหม่ได้ด้วยนะ**"*

- **ลูกค้า** — ปัจจุบันเป็นช่องพิมพ์อิสระ → ต้องเป็น dropdown + ปุ่มเพิ่มลูกค้าใหม่
- **ยา** — ดึงจากตาราง master (พี่ชมพู่จะ **ส่งไฟล์ให้**, A-p12 เขียนว่า "ส่งไฟล์ให้ · Database")
- **Batch Size** — ดึงค่ามาตรฐานต่อยาจาก DB ("ต้องดึง DataBase เพิ่ม")

### 1.3 Master ยาที่จะได้รับ (A-p12 — `ตารางรหัสผลิตภัณฑ์และเลขทะเบียนตำรับยา`)

คอลัมน์: `CODE` · `PRODUCT NAME` · `ชนิด` · `หน่วย` · `เลขทะเบียน` · `ลักษณะยา` · `หมายเหตุ`

- ตัวอย่าง: `UM-BA003 | BALAMINE-500 | S/C | TAB | 1A 80/50 | ยาเม็ดรูปกลมนูน เคลือบน้ำตาลสีขาว เรียบทั้งสองด้าน`
- **ชนิด (dosage form) ที่พบจริง:** `TAB` · `CAP` · `F/C` (film coated) · `S/C` (sugar coated) · `CRM` · `LIQ` · `INJ` · `GEL`
- **หน่วยที่พบจริง:** `TAB` · `CAP` · `KG.` · `LT.`
- แถวที่เป็นสีเทา = **ทะเบียนยกเลิก** → master ต้องมีธง active/ยกเลิก ไม่ใช่ลบทิ้ง
- `ลักษณะยา` = ช่อง "รูปร่างลักษณะยา" บนใบแจ้งผลิต → ต้องเก็บใน master

## 3. 🚦 สถานะงาน — 6 ขั้นปัจจุบันไม่พอ

### 3.1 สิ่งที่ขอเพิ่ม (A-p02 · A-p03 · A-p10)

- **`UNPLAN`** — *"ถ้าทำงานไปสลับกับฝ่ายขาย อาจขอให้ชะลอการผลิต จะปรับสถานะเป็น UNPLAN"* (มีในรายงาน A-p10 เป็นคอลัมน์จริง)
- **`แผน MM/YY`** — งานที่ลงแผนไว้เดือนไหน (`แผน06/26`, `แผน07/26`, `แผน11/26`, `แผน01-02/27`)
- **สถานะย่อยใต้ "กำลังผลิต"** — A-p02 เขียนว่า *"มีสถานะย่อยว่าต้องรอผลิตแจ้ง"*
- **จัดกลุ่มแดชบอร์ดใหม่** (A-p03): `Plan (รอแจ้งผลิต + มีแผนแล้ว) + WIP (ผลิต|แจ้ง|QC|QA|เข้าคลัง) = Pending Order`

### 3.2 สถานะจริงที่โรงงานใช้ (จาก A-p08/09/11 — ของจริง ไม่ใช่ที่ทีมขอโดยตรง)

```
แผน MM/YY → ชั่งวัตถุดิบรอผสม → ผสมยา → บดวัตถุดิบ → ตอกเม็ด →
รอเคลือบฟิล์ม → เคลือบฟิล์ม → รอเคลือบน้ำตาล → บรรจุแคปซูล →
รอตรวจวิเคราะห์ → รอเลือกยา → เลือกยา → รอบรรจุยา → บรรจุยา →
รอบรรจุหีบห่อ → บรรจุหีบห่อ → รอส่ง Checklist → ส่ง Checklist → เข้าคลัง
```
+ `Unplan` · `รอเลือกยา`

> 🔎 **ข้อสังเกตของ Claude:** สถานะพวกนี้ = "สถานีในสูตร (route)" ที่ระบบมีอยู่แล้ว
> ทางที่น่าจะสะอาดกว่าการเพิ่ม enum 20 ค่า คือ **derive สถานะที่แสดง จาก route + บันทึกผลผลิตล่าสุด**
> แล้วเก็บ enum เดิม 6 ค่าไว้เป็น "เฟส" — จะได้ไม่พัง dashboard/report ที่ผูกกับ enum เดิม (เจอ gotcha นี้มาแล้วตอน migration 0022)

## 5. 🧪 BOM / วัตถุดิบ — ทีมขอ "ถอย" จากที่ทำไว้

**ถูกขีดฆ่าทิ้ง 4 จุด** ทั้งใน B และ C:
- B-p03 / C-p07: หัวข้อ `A3 · เพิ่มวัตถุดิบ + ล็อต` — ขีดทิ้งทั้งหัวข้อ
- B-p07 / C-p14: ตาราง BOM ในการ์ดยา — กากบาททับ (เหลือแค่ **ขั้นตอนการผลิต**)
- B-p08 / C-p13: ตารางรายการวัตถุดิบต่อสูตร — กากบาททับ
- C-p12: `B2 · สร้างสูตร / BOM /` ขีดฆ่า เหลือ **"รูปแบบบรรจุ / ขั้นตอนการผลิต"** + เขียนกำกับ *"ยังไม่เพิ่มการใช้ BOM ตามที่คุณบรรเทิงแจ้ง"*

**สิ่งที่ขอแทน (B-p03 / C-p07 — "Comment จากฝ่ายวางแผน"):**
> *"เปลี่ยนจากกรอกวัตถุดิบทีละตัว เป็น **กรอกเฉพาะชื่อ product + บรรจุภัณฑ์** และมี **ใบติ๊ก พร้อม / ไม่พร้อม** และ **หมายเหตุ หากปล่อยได้บางส่วน**"*

→ ตรงกับบล็อก "ความพร้อมผลิต" ในใบแจ้งผลิต (§2.1) เป๊ะ

**การเบิกวัตถุดิบ (B-p10):**
> *"ในขั้นนี้เปลี่ยนเป็น **ผลิตกดขอเบิกวัตถุดิบ แล้วคลังเป็นคนเข้ามาติ๊กอนุมัติจ่ายของ**"* · *"Notification ไม่มี"*
> *"เบิกจำนวนเป็น Jobs"* · ขีดฆ่าปุ่ม "จ่ายทุกรายการ"
> เพิ่มคำว่า **"เบิกวัตถุดิบ / บรรจุภัณฑ์"** (C-p12)

## 6. 🧹 Line Clearance — ต้องทำทุกสถานี ไม่ใช่ครั้งเดียว

**นี่คือประเด็นที่ฝ่ายผลิตย้ำหนักที่สุด**

- **B-p12:** *"Line Clearance อยู่แล้วเริ่มผลิต และ**เข้าทุก stage** เพราะ Line ผลิตไม่ได้เป็น Line เดียว เช่น ตอกเม็ด → พัก → เปลี่ยนห้อง → บด → ฯลฯ"*
- **C-p25:** *"ในแต่ละสถานีจะมีการทำ Line clearance ของแต่ละห้อง — **หากบันทึกใหม่ จะเป็นการลบข้อมูลเก่าหรือไม่**"*
  → ต้องเก็บเป็น **หลายรายการ ไม่ทับกัน**
- **C-p25:** *"หากการทำยาชนิดเดียวกันต่อเนื่อง จะไม่ได้ทำ Line Clearance อีกครั้ง จะผลิตต่อเลย — **ขอให้เพิ่มช่องทางสำหรับการทำต่อ Lot ก่อนหน้าอีกช่อง**"*
- **B-p11:** *"ให้เป็นเงื่อนไขที่ต้องผ่าน **เป็นขั้นตอนแรกของสถานะ 'กำลังผลิต'** แทน เพราะเมื่อกด 'เริ่มผลิต' จะเป็นธุรการ แต่คนทำ Line Clearance จะเป็นพนักงาน/หัวหน้างานในขั้นกำลังผลิต"*

**ช่องที่ขอเพิ่มในฟอร์ม (B-p11, B-p12):**
- **ห้อง** (ทำห้องไหน)
- **จำนวนคน**
- **เวลา/ครั้ง แยกต่อแต่ละข้อ** (เคลียร์ของเก่า · washing · set-up)
- **หมายเหตุ** (ไว้ใส่ชื่อพนักงานที่ทำจริง ถ้ายังไม่มีบัญชี)

**ผู้ตรวจรับ (B-p12):** ⚠️ ขัดกับของเดิม
> *"Production ทำความสะอาด / Production ตรวจรับ } **คนละคน คนละ Role ใน Production**"*
> *"โดยปกติพนักงานในห้องจะเป็นคนทำ Line clearance และ**หัวหน้าห้องเป็นผู้ตรวจสอบ**"*

→ ตอนนี้ระบบให้ **QC** เป็นผู้ตรวจรับ · ทีมขอเปลี่ยนเป็น **หัวหน้าห้องฝ่ายผลิต**

## 8. 🔬 QC / QA — ของใหม่จากเอกสาร C (ปากกาแดง/ม่วง)

### 8.1 แยก OOS / NC / Deviation ออกจากกัน ⭐ (C-p24, C-p28, C-p30)

เขียนย้ำ **3 ที่** ว่า `deviation` ที่มีอยู่ต้องแตกเป็น **3 ประเภท**:

| | ย่อมาจาก | เลขที่เอกสาร |
|---|---|---|
| **OOS** | Out of Specification | `OOS No. ____` |
| **NC** | Non-conformance | `NC No. ____` |
| **Dev** | Deviation | `Dev No. ____` |

### 8.2 Workflow deviation ใหม่ (C-p28, C-p29)

```
① ใครก็เปิดได้ (ทุกหน่วยงานที่พบปัญหา) → แจ้ง QA
② QA ประเมิน + เลือกผู้รับผิดชอบแก้ไขเบื้องต้น:
     ☐ WHS   ☐ QC   ☐ PRD   ☐ ENG.     ← checkbox หรือ dropdown
     + แจ้งเตือนผู้รับผิดชอบ
③ หน่วยงานที่รับผิดชอบในข้อ ② บันทึกผลดำเนินการ → ส่งกลับ QA ติดตาม
④ QA อนุมัติ + ปิด
```

- **"กำหนดปิด" ยังไม่ต้องใส่ตอนเปิด** (B-p14 *"ยังไม่ต้องใส่ตอนเปิด"*)
- **บังคับ root cause + CAPA ตอนปิด** → ขีดฆ่าทิ้ง (C-p29, C-p30) เปลี่ยนเป็น **"การแก้ไขเบื้องต้น"** ของหน่วยงาน แล้ว QA ประเมินอีกที
- B-p14: *"หน่วยงานไหนพบปัญหาเปิดได้ · QA ต้องตรวจสอบ · Noti ให้ QA"*

### 8.3 In-process QC (C-p24 — ปากกาม่วง)

1. **เพิ่มการระบุ `valid date`** — เป็นวันที่ หรือเลือก **"ไม่กำหนด"**
2. **กำหนด level user เป็น 3 level** เพื่อลงผล / อนุมัติ
3. ⭐ **แยก "ผลวิเคราะห์" ออกจาก "ผลในกระบวนการผลิต"** — คนละอย่างกัน ตอนนี้ปนกันอยู่

### 8.4 QA Sample → เปลี่ยนความหมาย (C-p28)

- ขีดฆ่าชื่อ `QA Sample` → **"ตรวจ Finished product"**
- ช่อง `จุด/รอบเก็บตัวอย่าง` ("ปลายรอบบรรจุ") ขีดฆ่า → **วันที่ / เวลา**
- `จำนวน` → ระบุจำนวน
- `หน่วย` → **ผลผ่าน / ไม่ผ่าน**

### 8.5 คำขอแก้ไขย้อนหลัง (C-p34)

- ผู้อนุมัติ: ผู้บริหาร → **ระดับเภสัชกรขึ้นไป**

# คู่มือฝึกปฏิบัติ — เดินงานจริง 1 ล็อต ตั้งแต่เปิดจนปิดงาน

ภาคนี้พาคุณเดินงานผลิต **1 ล็อต ครบทั้งวงจร** ตั้งแต่ตั้งค่าระบบ เปิดงาน ผลิต ตรวจคุณภาพ ไปจนรับเข้าคลัง
อ่านเรียงจากต้นจนจบ แล้วลงมือทำตามในระบบจริงไปด้วย — ทำครบรอบเดียวก็ใช้งานเป็นทั้งระบบ

> 💡 **ทำเฉพาะขั้นที่เป็นหน้าที่ฝ่ายคุณก็ได้** — แต่ลองอ่านผ่านทุกขั้น จะเข้าใจว่าทำไมต้องรอฝ่ายอื่น
> และงานที่คุณส่งต่อไปนั้นฝ่ายถัดไปเอาไปทำอะไร

---

## เตรียมตัวก่อนเริ่ม

### บัญชีและบทบาทของคุณ

ทุกคนใช้ **บัญชีของตัวเอง** (อีเมล + รหัสผ่านส่วนตัว) ไม่มีบัญชีกลาง เพราะระบบต้องบันทึกได้ว่า
**ใครเป็นคนทำ** ทุกการกระทำ ตามหลัก GMP

ระบบมี **สิทธิ์ (role) 16 แบบ** — คนหนึ่งถือได้หลายสิทธิ์ · สิทธิ์ของคุณเห็นได้ที่ **ท้ายแถบเมนูซ้าย**

| สิทธิ์ | ตัวย่อ | ทำอะไรในภาคนี้ |
|---|---|---|
| ฝ่ายวางแผน | PLN | Part B ทั้งหมด · C1 |
| ฝ่ายผลิต | PROD | C2–C7 |
| หัวหน้าฝ่ายผลิต | PROD-L | C5 (ยืนยัน) · C8 (อนุมัติ) · **C10 (ส่งตรวจ QC)** |
| QC | QC | C9 (ลงผลตรวจ) |
| หัวหน้า QC | QC-L | C9 (อนุมัติผลตรวจ) · **C10 (QC ผ่าน / ตีกลับ)** |
| QA | QA | C11 (บันทึกจุดเก็บตัวอย่าง) · C12 · C13 (ตีกลับได้) |
| หัวหน้า QA | QA-L | C11 (อนุมัติจุดเก็บตัวอย่าง) · **C13 (ปล่อยผ่าน FG)** |
| คลังสินค้า | WH | C2 (กดพร้อม) · C14 |
| วิศวกรรม | ENG | A1 (สถานี) · A4 (วันซ่อม/สอบเทียบ) |
| บัญชีต้นทุน | COST | D7 (ต้นทุนค่าแรง) |
| ผู้บริหาร | MGR | ทำแทนได้เกือบทุกขั้น **ยกเว้นส่งตรวจ QC และลงนาม QC/QA** |
| ผู้ดูแลระบบ | ADM | Part A ทั้งหมด |

หัวหน้าฝ่ายอีก 4 สิทธิ์ — **หัวหน้าฝ่ายวางแผน (PLN-L) · หัวหน้าคลัง (WH-L) · หัวหน้าวิศวกรรม (ENG-L) · หัวหน้าบัญชีต้นทุน (COST-L)** —
ทำได้ทุกอย่างที่ฝ่ายตัวเองทำ + ดูแลบัญชีผู้ใช้ของฝ่ายตัวเอง (A6)

> 🔒 **บัญชีผู้บริหารและผู้ดูแลระบบต้องยืนยันตัวตน 2 ชั้น** — หลังใส่รหัสผ่าน ต้องกรอกรหัส 6 หลักจากแอป
> *Google Authenticator* หรือ *Microsoft Authenticator* ในมือถือทุกครั้งที่ล็อกอิน (ครั้งแรกระบบจะให้สแกน QR เพื่อตั้งค่า)
> ถ้ามือถือหาย ให้ผู้ดูแลระบบอีกคนกด **"รีเซ็ต MFA"** ในหน้าจัดการผู้ใช้

> 🔑 **หัวหน้าฝ่ายมีสิทธิ์ของลูกน้องเสมอ** — เช่น "หัวหน้าฝ่ายผลิต" ทำทุกอย่างที่ "ฝ่ายผลิต" ทำได้
> แต่ **ไม่ย้อนกลับ** — ฝ่ายผลิตไม่ได้สิทธิ์ของหัวหน้า นี่คือสิ่งที่ทำให้กฎ 2 ลายเซ็นทำงานได้จริง

### กฎ 2 ลายเซ็น — ทำไมบางขั้นต้องรออีกคน

หัวใจของระบบนี้คือ **คนทำกับคนรับรองต้องเป็นคนละคน** ระบบบังคับเองในฐานข้อมูล กดข้ามไม่ได้
มีทั้งหมด **6 ชุด** เจอครบในภาคนี้

| ชุด | ผู้ทำ | ผู้รับรอง | เจอที่ขั้น |
|---|---|---|---|
| Line Clearance | ฝ่ายผลิต | **หัวหน้าฝ่ายผลิต** | C5 |
| บันทึกผลผลิตรายวัน | ฝ่ายผลิต | **หัวหน้าฝ่ายผลิต** | C8 |
| ผลตรวจ In-process | QC | **หัวหน้า QC** | C9 |
| จุดเก็บตัวอย่าง (QA) | QA | **หัวหน้า QA** | C11 |
| ลงนาม QC / QA | — | **หัวหน้า QC / หัวหน้า QA** (ยืนยันรหัสผ่านซ้ำ) | C10 · C13 |
| คำขอแก้ไขย้อนหลัง | ใครก็ได้ | ผู้บริหาร / หัวหน้าฝ่ายที่เกี่ยว | E2 |

> 🔒 **ผู้บริหารลงนามขั้น QC/QA แทนไม่ได้** — ระบบบังคับว่าคนลงนามต้องถือสิทธิ์ **หัวหน้า QC / หัวหน้า QA** จริง
> ตามหลัก GMP ที่ว่าผู้ปล่อยผ่านต้องเป็นผู้มีคุณสมบัติของฝ่ายนั้น · พนักงาน QA กด **ตีกลับ** ได้ แต่ **ปล่อยผ่าน** ไม่ได้

---

### เส้นทางที่เราจะเดิน

งาน 1 ใบเดินผ่าน **6 สถานะหลัก** เรียงตายตัว ถอยหลังได้ทางเดียวคือ "ตีกลับ"

```
รอแจ้งผลิต ──► มีแผนแล้ว ──► กำลังผลิต ──► QC ──► QA ──► FG (เข้าคลัง)
   (PLN)         (PROD)       (PROD-L)    (QC-L) (QA-L)     (WH)
                                  ▲          │      │
                                  └──────────┴──────┘
                                      ตีกลับ (ต้องลงนาม)
```

| สถานะ | ใครเป็นคนเลื่อนไปขั้นถัดไป | ปุ่มที่กด |
|---|---|---|
| รอแจ้งผลิต | ฝ่ายวางแผน / ผู้บริหาร | **"ยืนยันแผนผลิต"** |
| มีแผนแล้ว | ฝ่ายผลิต / ผู้บริหาร | **"เริ่มผลิต"** |
| กำลังผลิต | **หัวหน้าฝ่ายผลิตเท่านั้น** (ระบบเช็กด่าน 4 ข้อก่อน — C10) | **"ส่งตรวจ QC"** |
| QC | **หัวหน้า QC เท่านั้น** | **"QC ผ่าน → ส่ง QA"** / **"QC ตีกลับ"** |
| QA | ปล่อยผ่าน = **หัวหน้า QA เท่านั้น** · ตีกลับ = QA | **"QA ปล่อยผ่าน → FG"** / **"QA ตีกลับ"** |
| FG (เข้าคลัง) | — จบงาน | (งานหายจากบอร์ด) |

> 🚫 **มีสถานะที่ 7 นอกเส้นทาง: "ยกเลิก"** — ใช้แทนการลบงาน (ข้อมูลไม่หาย ตรวจย้อนหลังได้)
> หัวหน้าแผนกยกเลิกได้เฉพาะงานที่ **ยังไม่เริ่มผลิต** · ผู้บริหาร/ผู้ดูแลระบบยกเลิกได้ทุกสถานะ **ยกเว้น FG**
> ต้องกรอกเหตุผล + รหัสผ่าน · ผู้บริหารกด **"คืนงาน"** ได้ · ดูวิธีที่ B5

> ⚠️ **"Status" กับ "สถานะ" ไม่ใช่เรื่องเดียวกัน** — ช่อง **Status** ในการ์ดข้อมูลงาน (เช่น `ไม่มีแผน` `มีแผน08/26`)
> เป็นข้อความอิสระที่ทีมใช้สื่อสารกันเอง **ไม่มีผลต่อด่าน GMP** ส่วน "สถานะ" 6 ขั้นข้างบนคือตัวที่ระบบบังคับจริง

# Part A — ตั้งค่าระบบ (ทำครั้งเดียว) 🔧

Part นี้ทำครั้งเดียวตอนเปิดใช้ระบบ หรือตอนมีของใหม่เข้ามา (ยาตัวใหม่ เครื่องใหม่ พนักงานใหม่)
ถ้าโรงงานคุณตั้งค่าไว้ครบแล้ว **ข้ามไป Part B ได้เลย**

> 🔑 แต่ละขั้นใน Part A ใช้สิทธิ์ต่างกัน — ดูในวงเล็บท้ายหัวข้อ · **ผู้บริหาร / ผู้ดูแลระบบ** ทำได้ทุกขั้น

## A1 · สถานีการผลิต (master) 🔧👔 *(วิศวกรรม / หัวหน้าฝ่ายผลิต / ผู้บริหาร)*

"สถานี" คือขั้นตอนการผลิตของโรงงาน เช่น เตรียมวัตถุดิบ · ผสมแห้ง · ตอกเม็ด · เคลือบฟิล์ม · บรรจุ
เป็นรายการกลางที่ทุกผลิตภัณฑ์หยิบไปใช้

📍 **เมนูซ้าย → ผลิตภัณฑ์ / ขั้นตอนการผลิต** แล้วกางแผง **"⚙️ ตั้งค่าสถานีการผลิต"**

![แผงตั้งค่าสถานีการผลิต — ตารางรหัส ชื่อสถานี ลำดับ และธงสถานีบรรจุ](manual-img/19b-stations.png)

🖱️ กด **"เพิ่มสถานี"** แล้วกรอก

| ช่อง | ตัวอย่าง | อธิบาย |
|---|---|---|
| รหัส (code) * | `ST-BAND` | ห้ามซ้ำ |
| ชื่อสถานี * | `คาดแคปซูล` | ชื่อที่ทุกคนจะเห็น |
| ลำดับ | `7` | ใช้เรียงในรายการ |
| ใช้งาน | ✓ | ติ๊กออก = ซ่อนจากรายการเลือก แต่ของเก่ายังอ้างถึงได้ |
| **แพ็ค** | ☐ | ติ๊กเฉพาะ **สถานีบรรจุ** |

> ⚠️ **ธง "แพ็ค" มีผลกับแดชบอร์ด** — งานที่บันทึกผลผลิตล่าสุดอยู่ที่สถานีที่ติ๊ก "แพ็ค"
> จะถูกนับเข้าช่อง **"แพ็ค"** ของบล็อก Pending Order · ถ้าไม่ติ๊กเลย ช่องนั้นจะเป็น 0 ตลอด

## A2 · ทะเบียนผลิตภัณฑ์ 👔📦 *(ผู้บริหาร / วางแผน / คลัง)*

📍 **เมนูซ้าย → ผลิตภัณฑ์ / ขั้นตอนการผลิต** → 🖱️ **"＋ เพิ่มผลิตภัณฑ์"**

![ฟอร์มเพิ่มผลิตภัณฑ์ — รหัส ชื่อ หน่วย REG NO. ชนิด และลักษณะยา](manual-img/18-product-form.png)

✍️ ช่องที่ต้องกรอก

| ช่อง | บังคับ | ตัวอย่าง | ไปโผล่ที่ไหน |
|---|:---:|---|---|
| รหัส (code) | ✓ | `UM-FE005` | คอลัมน์ CODE บนตารางบอร์ดงาน |
| ชื่อผลิตภัณฑ์ | ✓ | `FEBRATE-200` | ทุกที่ที่พูดถึงงานนี้ |
| หน่วย | | `TAB` · `CAP` | ล็อกให้งานที่ใช้ยาตัวนี้ |
| REG NO. | | `1A 119/59` | ช่อง REG. NO. บนใบแจ้งผลิต |
| ชนิด | | `TAB / CAP / F/C / CRM` | คอลัมน์ "ชนิด" |
| **ลักษณะยา** | | `ยาเม็ดกลมนูน เคลือบน้ำตาลสีขาว เรียบทั้งสองด้าน` | ช่อง **"รูปร่างลักษณะยา"** บนใบแจ้งผลิต |

> ⚠️ **รหัสยา · REG NO. · ลักษณะยา แก้ได้ที่หน้านี้ที่เดียว** — ในหน้ารายละเอียดงานจะเป็นแบบอ่านอย่างเดียว
> เพราะถ้าปล่อยให้แก้รายงาน ข้อมูลของยาตัวเดียวกันจะไม่ตรงกันระหว่างงาน

> 💡 **เพิ่มผลิตภัณฑ์ใหม่แล้ว ระบบแจ้งเตือน 🧪 ไปที่ฝ่ายผลิต** ให้มาตั้งขั้นตอนการผลิต (A3) ต่อ

> 💡 **ลบผลิตภัณฑ์มี 2 ระดับ** — ปุ่ม **"ลบ"** ธรรมดาจะเปลี่ยนเป็น "ปิดใช้งาน" ให้อัตโนมัติถ้ายังมีงานอ้างถึงอยู่ ·
> ส่วน **"🗑️ ลบถาวร"** (ผู้บริหารเท่านั้น) จะบอกก่อนว่าลบไม่ได้เพราะมีอะไรผูกอยู่ และต้องยืนยันด้วยรหัสผ่าน

## A3 · ขั้นตอนการผลิต (Route) ของผลิตภัณฑ์ 📋👔 *(วางแผน / หัวหน้าฝ่ายผลิต / ผู้บริหาร)*

Route คือ **ลำดับสถานีที่ยาตัวนี้ต้องเดินผ่าน** — ระบบใช้ Route ตัดสินว่า
บันทึกผลผลิตได้ที่สถานีไหนบ้าง · ต้องตรวจ in-process กี่สถานีถึงจะครบ · และงานอยู่สถานีอะไร

📍 ในการ์ดของผลิตภัณฑ์ → 🖱️ **"แก้ขั้นตอน"**

![แก้ขั้นตอนการผลิต — เลือกสถานีเรียงลำดับ พร้อมปุ่มเลื่อนขึ้น/ลง](manual-img/19-route-editor.png)

🖱️ เลือกสถานีทีละตัว จัดลำดับด้วย **"เลื่อนขึ้น" / "เลื่อนลง"** ใส่หมายเหตุได้ แล้วกด **"บันทึกลำดับสถานี"**

> ⚠️ **ยาที่ยังไม่มี Route จะขึ้นแถบเตือนสีแดงในหน้ารายละเอียดงาน** และบันทึกผลผลิตไม่ได้
> ถ้าเจอแถบนี้ให้กลับมาตั้ง Route ก่อน

## A4 · เครื่องจักร 🏭🔧 *(ฝ่ายผลิต / วิศวกรรม / ผู้บริหาร)*

📍 **เมนูซ้าย → เครื่องจักร** → 🖱️ **"＋ เพิ่มเครื่องจักร"**

![ฟอร์มเพิ่มเครื่องจักร — รหัส ชื่อ สถานี ห้อง สถานะ](manual-img/17-machine-form.png)

| ช่อง | ตัวอย่าง | หมายเหตุ |
|---|---|---|
| รหัสเครื่อง (code) * | `MC-001` | ห้ามซ้ำ |
| ชื่อเครื่อง * | `เครื่องตอกเม็ด A` | |
| สถานี | `ตอกเม็ด` | **ผูกเครื่องกับสถานี** — ตอนเลือกเครื่องให้ขั้นตอนของงาน ระบบจะโชว์เฉพาะเครื่องของสถานีนั้น |
| ห้อง | `ห้องตอก 1` | ไปโผล่ในบันทึก Line Clearance |
| สถานะ | พร้อมใช้ | 5 ค่า ดูด้านล่าง |

**สถานะเครื่องจักร 5 ค่า:** พร้อมใช้ · กำลังใช้งาน · ทำความสะอาด · ซ่อมบำรุง · ถึงกำหนดสอบเทียบ

> ⚠️ **เครื่องที่อยู่สถานะ "ซ่อมบำรุง" หรือ "ถึงกำหนดสอบเทียบ" จะไม่ขึ้นให้เลือกในฟอร์มบันทึกผลผลิต**
> — ตั้งใจกันไม่ให้เผลอบันทึกว่าใช้เครื่องที่ยังใช้ไม่ได้

> 🔑 **กำหนดวันซ่อมบำรุง / วันสอบเทียบครั้งหน้า** เป็นสิทธิ์ของ **ฝ่ายวิศวกรรม** และผู้บริหารเท่านั้น
> ฝ่ายผลิตเพิ่ม/แก้ทะเบียนเครื่องได้ แต่ตั้ง 2 วันนี้ไม่ได้

> 💡 **เครื่องที่ใกล้/เลยกำหนดซ่อมหรือสอบเทียบ (ภายใน 7 วัน)** ระบบส่งแจ้งเตือน 🛠️ ให้ฝ่ายวิศวกรรมอัตโนมัติทุกเช้า
> (เตือนซ้ำสัปดาห์ละครั้งจนกว่าจะเลื่อนวันกำหนดใหม่)

## B1 · สร้างงานผลิตใหม่ 📋 *(ฝ่ายวางแผน / ผู้บริหาร)*

📍 **เมนูซ้าย → บอร์ดงาน** → 🖱️ ปุ่ม **"＋ สร้างงานใหม่"** มุมขวาบน

![หน้าสร้างงานผลิตใหม่ — เลือกบริษัท ลูกค้า ผลิตภัณฑ์ และจำนวนใบที่จะสร้าง](manual-img/25-new-job-filled.png)

✍️ กรอกตามนี้

| ช่อง | บังคับ | อธิบาย |
|---|:---:|---|
| **บริษัท** | ✓ | ตัวกำหนดชุดเลขงาน — **เลือกผิดแก้ทีหลังไม่ได้** |
| **ลูกค้า / หน่วยงาน** | ✓ | เลือกจากทะเบียนลูกค้า (พิมพ์เองอิสระไม่ได้) |
| **ผลิตภัณฑ์ (ยา)** | ✓ | เลือกจากทะเบียน · **หน่วยจะถูกล็อกตามยาที่เลือกทันที** |
| จำนวนผลิต | | Batch Size |
| ใบคำขอ | | เลขที่ใบสั่งผลิตจากลูกค้า — ใบที่สร้างพร้อมกันใช้เลขนี้ร่วมกัน |
| C.P.O DATE | | วันที่ลูกค้าสั่งผลิต |
| กำหนดส่ง (due date) | | |
| รูปแบบบรรจุ + ขนาดบรรจุ 1–3 | | ตรงกับช่องบนใบแจ้งผลิต F.PLN.01 |
| หมายเหตุ | | ข้อความที่จะไปอยู่บนใบแจ้งผลิต (บริษัท POND ใช้ช่องนี้เป็นหลัก) |
| **จำนวนใบที่จะสร้าง** | | สร้างทีเดียวได้สูงสุด **50 ใบ** เลขงานไล่ต่อกันอัตโนมัติ |

🖱️ กด **"สร้างงานผลิต"**

✅ **ผลที่ควรเห็น** — กลับมาที่บอร์ดงาน มีงานใหม่อยู่คอลัมน์ **"รอแจ้งผลิต"** พร้อมเลขงานที่ระบบออกให้

> ⚠️ **ไม่มีช่อง LOT No. ในหน้านี้ — ถูกต้องแล้ว** เลขล็อตเป็นของฝ่ายผลิตที่รู้หน้างานจริง
> จะไปกรอกที่ขั้น C3

> 💡 **สร้างทีละหลายใบใช้ตอนไหน** — ลูกค้าสั่งยาตัวเดียวกันหลายล็อตในใบคำขอเดียว
> ใส่ "จำนวนใบที่จะสร้าง" เป็น 5 ระบบจะออกเลขงาน 5 เลขให้ในครั้งเดียว

## B2 · ดูงานบนบอร์ด 👀 *(ทุกฝ่าย)*

📍 **เมนูซ้าย → บอร์ดงาน**

![บอร์ดงาน — การ์ดงานเรียงตามสถานะ พร้อมช่องค้นหาและตัวกรอง](manual-img/20-board.png)

- **การ์ดแบ่งตามสถานะ 6 ขั้น** — สีของป้ายบอกสถานะ
- **🔍 ค้นหา** ได้ด้วย เลขงาน / Lot / ลูกค้า / ชื่อยา
- **ตัวกรอง** — สถานะ · บริษัท · **"🔴 เฉพาะงานมีปัญหา"** (= ติดธงปัญหา **หรือ** มี Incident Case ที่ยังไม่ปิด)
- ป้ายปัญหา 3 แบบ: 🔴 ติดปัญหา · 🟡 รอแก้ไข · 🟠 ล่าช้า · และป้าย **🚨 Incident N** เมื่อมีเคสเปิดค้าง
- **ตัวกรองจำค่าไว้** — เข้าหน้างานแล้วกดย้อนกลับ หรือกด "← กลับบอร์ดงาน" ตัวกรองชุดเดิมยังอยู่
- งานที่ **ยกเลิก** จะซ่อนจากบอร์ด — ดูได้ที่ตัวกรองสถานะ **"🚫 งานที่ยกเลิก"**

> 💡 **งานที่รับเข้าคลัง (FG) แล้วจะหายไปจากบอร์ด** — ไม่ได้ถูกลบ ยังค้นหาเจอและเปิด eBR ได้
> แค่ไม่รกบอร์ดของงานที่ยังเดินอยู่

🖱️ **กดที่การ์ด** เพื่อเข้าหน้ารายละเอียดงาน — ที่ที่งานทั้งหมดเกิดขึ้น

![หน้ารายละเอียดงานทั้งหน้า — แถบสถานะ การ์ดข้อมูลงาน และการ์ดงานแต่ละส่วนเรียงลงมา](manual-img/22-job-detail.png)

## B3 · การ์ดข้อมูลงาน 📇 *(แก้ได้ตามฝ่าย)*

การ์ดบนสุดของหน้ารายละเอียดงาน — รวมข้อมูลทั้งหมดของงานใบนี้

![การ์ดข้อมูลงาน — Job No. บริษัท ลูกค้า ผลิตภัณฑ์ แผน และรูปแบบบรรจุ](manual-img/23-job-info.png)

🖱️ กด **"✏️ แก้ไขข้อมูล"** เพื่อเข้าโหมดแก้ไข แก้หลายช่องแล้วกด **"บันทึก"** ทีเดียว

![โหมดแก้ไขการ์ดข้อมูลงาน — ช่องที่ฝ่ายคุณแก้ไม่ได้จะถูกปิดไว้](manual-img/27-job-edit.png)

**ใครแก้ช่องไหนได้ และช่องไหนล็อกเมื่อไร**

| ช่อง | ฝ่ายที่แก้ได้ | ล็อกเมื่อสถานะถึง |
|---|---|---|
| Status · เดือนแผน · หมายเหตุ | วางแผน + ผลิต | ไม่ล็อก |
| กำหนดส่ง | วางแผน | ไม่ล็อก |
| ลูกค้า · C.P.O DATE · ใบคำขอ | วางแผน (ใบคำขอ = ทั้งสองฝ่าย) | **FG** |
| แผนเริ่ม · แผนเสร็จ | ผลิต | **FG** |
| Batch Size · รูปแบบบรรจุ · Pack Size 1–3 | วางแผน | **กำลังผลิต** |
| LOT No. (Batch NO.) | ผลิต | ไม่ล็อก |
| วันผลิต · วันหมดอายุ | ทั้งสองฝ่าย (ต้องมีเลขล็อตก่อน) | ไม่ล็อก |

> 🔒 **ช่องที่ล็อกแล้วยังแก้ได้ แต่ต้องระบุเหตุผล** — ระบบจะขอเหตุผลก่อนบันทึก แล้วเก็บลงประวัติ (Audit)
> ตัวอย่างเหตุผลที่ใช้จริง: *"ฝ่ายขายแจ้งแก้จำนวนสั่งผลิตหลังเปิดงาน"*

> ⚠️ **Job No. · รหัสยา · REG NO. · ลักษณะยา แก้ที่นี่ไม่ได้เลย** — เลขงานระบบออกให้
> ส่วนข้อมูลยาต้องไปแก้ที่หน้าทะเบียนผลิตภัณฑ์ (A2)

## B4 · ปริ้นใบแจ้งผลิต F.PLN.01 🖨️ *(ฝ่ายวางแผน / ผู้บริหาร)*

ใบแจ้งผลิตคือกระดาษที่ส่งลงหน้างาน — ระบบพิมพ์ให้เหมือนฟอร์มกระดาษเดิมทุกช่อง

📍 **บอร์ดงาน → ปุ่ม "🖨️ ปริ้นใบแจ้งผลิต"** (เห็นเฉพาะฝ่ายวางแผนกับผู้บริหาร)

![หน้าปริ้นใบแจ้งผลิต — เลือกบริษัท กรองงาน ติ๊กงานที่จะพิมพ์ และตั้งขอบกระดาษ](manual-img/61-print-notice.png)

**ขั้นตอน**

1. 🖱️ เลือก **รูปแบบใบ (บริษัท)** — UMEDA และ POND ใช้ฟอร์มคนละแบบ
2. 🖱️ กรองงานด้วย **ขั้นตอน** · **C.P.O DATE** (ปี / เดือน+ปี / วัน) หรือช่อง **ค้นหา**
3. 🖱️ **ติ๊กงาน** ที่จะพิมพ์ (หรือกด "ติ๊กทั้งหมดที่กรองอยู่")
4. 🖱️ กด **"👁 ดูตัวอย่าง"** เพื่อตรวจก่อนเปลืองกระดาษ
5. 🖱️ กด **"🖨️ ปริ้นใบแจ้งผลิต / PDF"**

![ตัวอย่างใบแจ้งผลิต F.PLN.01 — A4 หนึ่งแผ่นได้ 2 Job มีเส้นประกลางไว้ฉีก](manual-img/66-notice-preview.png)

> 💡 **A4 หนึ่งแผ่น = 2 Job** มีเส้นประกลางไว้ฉีกครึ่ง · ช่อง LOT NO. / MFG. DATE / EXP.DATE
> เว้นว่างไว้ให้เขียนมือหน้างานตามฟอร์มเดิม

> ⚠️ **ในหน้าต่างพิมพ์ ตั้ง "ขนาดกระดาษ / Paper size" = A4** (อยู่ใน *More settings*) — ถ้าเป็น Letter
> (ค่าเริ่มต้นของเครื่องพิมพ์หลายรุ่น) ขอบขวาจะถูกตัด · Scale ปล่อยเป็นค่าเริ่มต้นได้
> ปุ่มนี้สร้างไฟล์ PDF ก่อนแล้วค่อยสั่งพิมพ์ **จึงไม่มีวันที่/URL ของเบราว์เซอร์ติดมาบนกระดาษ**

> 💡 **ไม่อยากตั้ง A4 ทุกครั้ง** — ตั้งค่าเริ่มต้นของเครื่องพิมพ์ใน Windows (Printing preferences) เป็น A4 ครั้งเดียว

> 💡 ปรับ **ขนาดขอบกระดาษ 4 ด้าน** ได้ที่ท้ายหน้า (ค่าเริ่มต้น 0.32 นิ้ว) —
> เครื่องพิมพ์ส่วนใหญ่พิมพ์ชิดขอบเกิน ~4 มม. ไม่ได้ ตั้งต่ำกว่านั้นเบราว์เซอร์อาจย่อทั้งหน้าให้เอง

## B5 · ยกเลิกงาน / คืนงาน 🚫 *(หัวหน้าแผนก / ผู้บริหาร)*

ระบบ **ไม่มีการลบงาน** — งานที่ไม่ผลิตแล้วให้ **"ยกเลิก"** แทน ข้อมูลทุกอย่างยังอยู่ ตรวจย้อนหลังได้ (หลัก ALCOA ของ GMP)

📍 หน้ารายละเอียดงาน → 🖱️ **"🚫 ยกเลิกงานนี้"** → ✍️ **เหตุผล** (อย่างน้อย 5 ตัวอักษร) + **รหัสผ่านของคุณ** → ยืนยัน

![ปุ่มยกเลิกงาน — ต้องกรอกเหตุผลและรหัสผ่าน](manual-img/26-job-cancel.png)

| ใคร | ยกเลิกได้เมื่อ |
|---|---|
| หัวหน้าแผนก (ทุกฝ่าย) | งาน **ยังไม่เริ่มผลิต** (รอแจ้งผลิต / มีแผนแล้ว) |
| ผู้บริหาร / ผู้ดูแลระบบ | ทุกสถานะ **ยกเว้น FG** · และกด **"↩️ คืนงานนี้ (ยกเลิกผิด)"** ได้ (ต้องกรอกเหตุผล + รหัสผ่านเหมือนกัน) |

✅ **ผลที่ควรเห็น** — งานหายจากบอร์ด · เปิดดูได้จากตัวกรอง **"🚫 งานที่ยกเลิก"** · หน้างานมีแถบ **"🚫 ถูกยกเลิก"**
พร้อมผู้ยกเลิก/เหตุผล และ **ทั้งหน้าเป็นแบบอ่านอย่างเดียว** (ยกเว้น Incident Case ที่ QA ยังปิดต่อได้)

> 💡 คำขอแก้ไขที่ค้างของงานนั้นถูกปิดให้อัตโนมัติ · ฝ่ายวางแผนได้แจ้งเตือน · งานยกเลิกไม่ถูกนับในแดชบอร์ด/ใบปริ้น

การ์ดในหน้านั้นเรียงจากบนลงล่างตามลำดับที่ใช้จริง จึงทำตามลงมาได้เลย

## C1 · ยืนยันแผนผลิต 📋 *(ฝ่ายวางแผน / ผู้บริหาร)*

🔑 เข้าด้วยบัญชี **ฝ่ายวางแผน** · 📍 เปิดงานที่สถานะ **"รอแจ้งผลิต"**

หาการ์ด **"ดำเนินการ"** แล้ว 🖱️ กด **"ยืนยันแผนผลิต"**

![การ์ดดำเนินการ — ปุ่มยืนยันแผนผลิตของฝ่ายวางแผน](manual-img/28-job-pending.png)

✅ สถานะเปลี่ยนเป็น **"มีแผนแล้ว"** · แถบขั้นตอนด้านบนขยับไปช่องที่ 2

![แถบสถานะ 6 ขั้นของงาน — ขั้นที่ผ่านแล้วมีเครื่องหมายถูก](manual-img/24-stepper.png)

> 💡 **อยากบอกทีมว่างานลงแผนเดือนไหน** ให้ตั้งช่อง **Status** ในการ์ดข้อมูลงานเป็น `มีแผน`
> แล้วเลือก **เดือนแผน** — บนบอร์ดจะแสดงเป็น `มีแผน08/26`

## C2 · ลงรายการเบิกวัตถุดิบ/บรรจุภัณฑ์ 🏭📦 *(ผลิตลงรายการ · คลังกดพร้อม)*

**แบ่งหน้าที่ชัดเจน:** ฝ่ายผลิตรู้ว่างานนี้ต้องใช้อะไร → ลงรายการ ·
ฝ่ายคลังเห็นของจริง → กดว่าพร้อมหรือไม่พร้อม

### ① ฝ่ายผลิตลงรายการ

🔑 บัญชี **ฝ่ายผลิต** · หาการ์ด **"เบิกวัตถุดิบ/บรรจุภัณฑ์"** → 🖱️ **"＋ เพิ่มรายการเบิก"**

![การ์ดเบิกวัตถุดิบ/บรรจุภัณฑ์ พร้อมปุ่มเพิ่มรายการ](manual-img/30-materials-card.png)

✍️ กรอก **ชื่อวัตถุดิบ/บรรจุภัณฑ์** (เช่น `แป้งข้าวโพด` · `ขวด HDPE 100 ml`) ·
**ประเภท** · **จำนวนที่เบิก** · **หน่วย** (`kg` · `ม้วน` · `ใบ`) · หมายเหตุ

> 💡 พอบันทึกแล้วจะขึ้น **"✓ เพิ่มแล้ว — พิมพ์รายการถัดไปได้เลย"** ฟอร์มเคลียร์ให้เอง
> ลงรายการยาว ๆ ได้ต่อเนื่องไม่ต้องกดเปิดใหม่ทุกครั้ง · ฝ่ายคลังได้แจ้งเตือน 🧾 ให้เอง (ลงหลายรายการติดกันได้ใบเดียว)

### ② ฝ่ายคลังกดสถานะความพร้อม

🔑 บัญชี **คลังสินค้า** — 🖱️ กดที่ป้ายสถานะของแต่ละรายการ แล้วเลือก **พร้อม / ไม่พร้อม**

![รายการเบิกในมุมมองฝ่ายคลัง — กดป้ายเพื่อเลือกสถานะความพร้อม](manual-img/47-materials-wh.png)

> 🔑 **ฝ่ายผลิตเห็นสถานะแต่กดไม่ได้ · ฝ่ายคลังกดได้แต่เพิ่ม/ลบรายการไม่ได้** — ตั้งใจให้เป็นแบบนี้
> เพื่อไม่ให้ฝ่ายเดียวทั้งขอทั้งยืนยันเอง

> 🔒 **ด่าน GMP: ของยังไม่พร้อม = บันทึกผลผลิต (C7) ไม่ได้** — งานต้องมีรายการเบิกอย่างน้อย 1 รายการ
> และฝ่ายคลังกด **"พร้อม"** ครบทุกรายการ หน้างานจะบอกเหตุผลและปิดฟอร์มบันทึกไว้จนกว่าจะครบ

> 💡 **ฝ่ายคลังมีหน้ารวมให้กดทีเดียวหลายงาน** ที่ 📍 **เมนูซ้าย → เบิกวัตถุดิบ / บรรจุภัณฑ์**
> ไม่ต้องเปิดทีละงาน

![หน้ารวมเบิกวัตถุดิบข้ามงาน — ฝ่ายคลังกดสถานะได้จากที่เดียว](manual-img/83-job-materials.png)

## C3 · กรอก LOT No. 🏭 *(ฝ่ายผลิต)* ⚠️ ห้ามข้าม

🔑 บัญชี **ฝ่ายผลิต** · การ์ดข้อมูลงาน → 🖱️ **"✏️ แก้ไขข้อมูล"** → ✍️ ใส่ **LOT No. (Batch NO.)**
จากนั้นใส่ **วันผลิต** และ **วันหมดอายุ** ได้ (2 ช่องนี้จะเปิดให้กรอกก็ต่อเมื่อมีเลขล็อตแล้ว)

> ⚠️ **ไม่มีเลขล็อต = กด "เริ่มผลิต" ไม่ได้** — หน้างานจะขึ้นแถบเตือนสีเหลือง
> นี่เป็นด่าน GMP: ทุกอย่างที่บันทึกต่อจากนี้ต้องผูกกับเลขล็อตที่ตามย้อนได้

## C4 · เลือกเครื่องจักรของแต่ละขั้นตอน 🏭 *(ฝ่ายผลิต)*

งานหนึ่งเดินผ่านหลายสถานีตาม Route — แต่ละสถานีใช้เครื่องอะไรบ้าง กรอกที่นี่

🖱️ เลือก **แท็บขั้นตอน** ที่ต้องการก่อน (แถบแท็บจะบอกจำนวนเครื่องและจำนวนบันทึกของแต่ละขั้น)

![แท็บขั้นตอนการผลิตของงาน — บอกจำนวนเครื่องและบันทึกของแต่ละขั้น](manual-img/31-route-tabs.png)

แล้วในการ์ด **"เครื่องจักรของขั้นตอนนี้"** 🖱️ กด **"＋ เพิ่ม"**

![การ์ดเครื่องจักรของขั้นตอน — รายชื่อเครื่องพร้อมสถานะและปุ่มถอดออก](manual-img/32-route-machines.png)

> 💡 **ระบบโชว์เฉพาะเครื่องของสถานีนั้น** — เพราะตอนตั้งทะเบียนเครื่อง (A4) เราผูกเครื่องกับสถานีไว้แล้ว
> ถ้าไม่เห็นเครื่องที่ต้องการ แปลว่าเครื่องนั้นยังไม่ได้ผูกกับสถานีนี้

## C5 · Line Clearance (เตรียมสายการผลิต) 🏭 *(ผลิตทำ · หัวหน้ายืนยัน)* ⚠️ สำคัญ

**ทำแยกทีละขั้นตอน × ทีละเครื่อง** — ไม่ใช่ครั้งเดียวจบทั้งงาน

### ① ฝ่ายผลิตติ๊กและบันทึก

🔑 บัญชี **ฝ่ายผลิต** · การ์ด **"Line Clearance (เตรียมสายการผลิต)"** →
🖱️ **"+ บันทึกการเคลียร์ไลน์"**

![ฟอร์ม Line Clearance — 3 ข้อติ๊ก พร้อมช่องห้อง จำนวนคน และเวลา set-up](manual-img/39-lc-form.png)

✍️ ติ๊กและกรอก

| รายการ | หมายเหตุ |
|---|---|
| ☐ เคลียร์ของเก่า/รุ่นก่อนออกจากไลน์ | ใส่ **เวลา** ได้ |
| ☐ ทำความสะอาด (washing) | ใส่ **เวลา** ได้ |
| ☐ ตั้งเครื่อง (set-up) | |
| ห้อง | เช่น `ห้องตอก 1` |
| จำนวนคน · เวลา set-up (นาที) | |
| หมายเหตุ | เช่น ชื่อพนักงานที่ทำจริง |

> ⚠️ **ต้องติ๊กอย่างน้อย 1 ข้อ** ถึงจะยืนยันได้

### ② หัวหน้าฝ่ายผลิตยืนยัน

🔑 บัญชี **หัวหน้าฝ่ายผลิต** (หรือผู้บริหาร) → 🖱️ กดยืนยัน

![Line Clearance ที่ผ่านแล้ว — แสดงผู้ทำ ผู้ยืนยัน และเวลาที่บันทึก](manual-img/33-line-clearance.png)

✅ ป้ายเปลี่ยนเป็น **"ผ่านแล้ว ✓"** พร้อมชื่อ **ผู้ทำ** และ **ผู้ยืนยัน**

> 🔒 **ผู้ยืนยันต้องเป็นคนละคนกับผู้ทำ** — ถ้าเป็นคนเดียวกันระบบจะขึ้นว่า
> *"ผู้ยืนยันต้องเป็นคนละคนกับผู้ทำ (รอหัวหน้าฝ่ายผลิตมายืนยัน)"* และกดไม่ผ่าน

## C6 · เริ่มผลิต 🏭 *(ฝ่ายผลิต / ผู้บริหาร)*

การ์ด **"ดำเนินการ"** → 🖱️ **"เริ่มผลิต"**

✅ สถานะเปลี่ยนเป็น **"กำลังผลิต"** — ตั้งแต่นี้ไปถึงบันทึกผลผลิตได้

> ⚠️ **ต้องมี LOT No. ก่อน** (C3) ไม่งั้นปุ่มนี้จะกดไม่ผ่าน

## C7 · บันทึกผลผลิตรายวัน 🏭 *(ฝ่ายผลิต)*

บันทึกได้เฉพาะตอนสถานะ **"กำลังผลิต"** และ **วัตถุดิบพร้อมครบ** (C2) · บันทึก **แยกตามขั้นตอน** — เลือกแท็บขั้นตอนก่อนเสมอ

🖱️ การ์ด **"บันทึกผลผลิตรายวัน"** → **"+ บันทึกผลผลิต"**

![ฟอร์มบันทึกผลผลิตรายวัน — วันที่ กะ ช่วงเวลา เครื่องจักร ยอดผลิต ของเสีย นาที และจำนวนคน](manual-img/38-record-form.png)

| ช่อง | บังคับ | หมายเหตุ |
|---|:---:|---|
| วันที่บันทึก | ✓ | |
| กะ | | กะเช้า / กะดึก |
| ช่วงเวลาปกติ / OT | | |
| เครื่องจักรที่ใช้ | | โชว์เฉพาะเครื่องของขั้นตอนนี้ · **เครื่องที่ซ่อม/สอบเทียบจะไม่ขึ้น** |
| ยอดที่ต้องการ | ✓ | มีช่อง **หน่วยแยกของตัวเอง** |
| ยอดผลิตได้ (output) | ✓ | มีหน่วยแยก |
| ของเสีย (loss) | | มีหน่วยแยก |
| นาทีทำงาน | | 0–1440 |
| จำนวนคน | | |
| หมายเหตุ | | |

> 💡 **แต่ละช่องเลือกหน่วยเองได้** (กล่อง · แผง · kg. · ซอง) เพราะหน้างานจริงนับคนละหน่วยกัน
> เช่นตั้งต้นเป็น kg. แต่ผลิตได้เป็นแผง

> ⚠️ **กรอกไม่ครบจะได้แจ้งเตือน 📋 "ข้อมูลไม่ครบ"** — ระบบเช็ก กะ · ช่วงเวลา · นาที · จำนวนคน
> แล้วบอกว่าขาดช่องไหนบ้าง (ไม่ได้ห้ามบันทึก แต่เตือนให้กลับมาเติม)

> 💡 **เน็ตหลุดกลางทางไม่หาย** — ระบบเก็บบันทึกที่ยังส่งไม่สำเร็จไว้ในเครื่อง แล้วส่งซ้ำให้เอง
> และกันไม่ให้เกิดแถวซ้ำถ้าส่งไปแล้วจริง · แท็บเล็ตที่ใช้ร่วมกัน บันทึกค้างของแต่ละคนแยกกัน (ไม่ถูกส่งในนามคนอื่น) ·
> ถ้าหลุดจากระบบระหว่างนั้น บันทึกค้างยังอยู่ — ล็อกอินใหม่แล้วระบบส่งให้เอง

> 💡 **กะดึกหลังเที่ยงคืน** วันที่ตั้งต้นของฟอร์มเป็นวันตามเวลาไทยเสมอ

> 💡 บันทึกใหม่ทุกแถว ระบบส่งแจ้งเตือน 🔬 ให้พนักงาน QC มาตรวจ in-process (C9)

![ตารางบันทึกผลผลิต — แสดงกะ ช่วงเวลา เครื่องจักร ยอด และสถานะการอนุมัติของแต่ละแถว](manual-img/34-records.png)

## C8 · หัวหน้าอนุมัติบันทึกผลผลิต 🏭 *(หัวหน้าฝ่ายผลิต)*

ทุกแถวที่พนักงานบันทึกจะขึ้นสถานะ **"รอหัวหน้าฝ่ายผลิตพิจารณา"**

🔑 บัญชี **หัวหน้าฝ่ายผลิต** (หรือผู้บริหาร) → 🖱️ กด **"อนุมัติ"** หรือ **"ไม่อนุมัติ"** ในคอลัมน์ "การอนุมัติ"

> 💡 **ไม่ต้องไล่เปิดทีละงาน** — 📍 **เมนูซ้าย → ⏳ รออนุมัติ** รวมทุกรายการที่รอคุณ (ตัวเลขบนเมนูคือจำนวนที่ค้าง)
> กดแจ้งเตือนก็พาไปถึงแท็บขั้นตอนที่มีรายการรออยู่ตรง ๆ

> 💡 **อนุมัติทีเดียวหลายแถวได้** — ติ๊กหลายแถวแล้วกดครั้งเดียว ระบบจะ **ข้ามบันทึกของตัวเองให้อัตโนมัติ**
> แล้วรายงานว่าข้ามไปกี่รายการ

> ⚠️ **ไม่อนุมัติต้องระบุเหตุผล** และ **บันทึกที่ถูกตีกลับจะไม่ถูกนับใน KPI บนแดชบอร์ด**

**กติกาการแก้บันทึก** (ใช้แบบเดียวกันทั้งบันทึกผลผลิต · ผลตรวจ in-process · จุดเก็บตัวอย่าง)

| สถานะของรายการ | แก้ยังไง |
|---|---|
| รออนุมัติ | **ผู้บันทึกแก้ตรงได้เลย** (คนอื่นแก้ไม่ได้ · เปลี่ยนสถานี/เครื่องไม่ได้) |
| ไม่อนุมัติ (ถูกตีกลับ) | ผู้บันทึกแก้แล้ว **กลับเป็น "รออนุมัติ"** + หัวหน้าได้แจ้งเตือนอีกครั้ง |
| อนุมัติแล้ว | ต้อง **ยื่นคำขอแก้ไข (Amendment)** ให้หัวหน้าอนุมัติ — ดู E2 |

## C9 · ตรวจระหว่างผลิต (In-process QC) 🔬 *(QC ลงผล · หัวหน้า QC อนุมัติ)*

### ① QC ลงผลตรวจ

🔑 บัญชี **QC** · การ์ด **"ตรวจระหว่างผลิต (In-process QC)"** → 🖱️ **"＋ บันทึกผลตรวจ"**

![ฟอร์มบันทึกผลตรวจ in-process — เลือกแถวบันทึกผลผลิต หัวข้อที่ตรวจ ค่า ผล และ Valid date](manual-img/40-inprocess-form.png)

✍️ กรอก **หัวข้อที่ตรวจ** (เช่น น้ำหนักเม็ด / ความแข็ง / ความชื้น) · **ค่าที่วัดได้** + หน่วย ·
**ผล** (ผ่าน / ไม่ผ่าน) · **Valid date (ใช้ได้ถึง)** · หมายเหตุ

> ⚠️ **ต้องเลือกแถวบันทึกผลผลิตที่ตรวจเสมอ** (รายการด้านบนของฟอร์ม) — เพื่อตามได้ว่าผลนี้มาจากการผลิตรอบไหน
> และระบบใช้ข้อนี้เช็กว่า "บันทึกผลผลิตทุกแถวมีผลตรวจแล้ว" ก่อนส่ง QC (C10)

### ② หัวหน้า QC อนุมัติ

🔑 บัญชี **หัวหน้า QC** → 🖱️ **"อนุมัติ"** / **"ไม่อนุมัติ"** (ไม่อนุมัติต้องระบุเหตุผล)

![ตารางผลตรวจ in-process — แถบความคืบหน้าตามสถานี และสถานะการอนุมัติรายแถว](manual-img/35-inprocess.png)

> 🔒 **นับเฉพาะผลที่หัวหน้า QC อนุมัติแล้ว** — แถบ **"ความคืบหน้า QC ตามสูตร"** ด้านบนบอกว่าครบกี่สถานีแล้ว

> ⚠️ **ผลตรวจ "ไม่ผ่าน" → เมื่อหัวหน้า QC พิจารณา ระบบเปิด Incident Case ให้อัตโนมัติ** (ดู C12)

> 💡 **QC/QA ทำงานจากหน้าเดียวได้** — 📍 **เมนูซ้าย → ตรวจ QC / QA** รวมงานที่รอฝ่ายคุณเป็นการ์ด
> (แท็บ *ของฉัน* / *ทั้งหมด*) บอกว่างานไหน ขั้นตอนไหน ต้องทำอะไร · หัวหน้ากดอนุมัติ/ลงนามท้ายการ์ดได้เลย

![หน้าตรวจ QC / QA — การ์ดงานที่รอ พร้อมปุ่มอนุมัติ/ลงนามท้ายการ์ด](manual-img/81-quality.png)

> 🔑 **ฝ่ายอื่นบันทึก/แก้ผลตรวจ in-process ไม่ได้** — ถ้าเจอปัญหาให้แจ้ง QC หรือเปิด Incident Case แทน

## C10 · ส่งตรวจ QC แล้ว QC ตัดสิน 🏭🔬

### ① หัวหน้าฝ่ายผลิตส่งตรวจ

🔑 บัญชี **หัวหน้าฝ่ายผลิต** → การ์ด **"ดำเนินการ"** → 🖱️ **"ส่งตรวจ QC"**

> ⚠️ **ขั้นนี้หัวหน้าฝ่ายผลิตเท่านั้นที่กดได้** — พนักงานฝ่ายผลิตและผู้บริหารกดแทนไม่ได้

🔒 **ด่านส่งเข้า QC 4 ข้อ** — หน้างานแสดงเป็นเช็กลิสต์ ข้อไหนยังไม่ผ่านจะบอกว่าขาดอะไร

| ข้อ | ต้องเป็นแบบนี้ |
|---|---|
| 1 | มีบันทึกผลผลิตที่อนุมัติแล้วอย่างน้อย 1 รายการ |
| 2 | **ทุกขั้นตอนใน Route** มีบันทึกผลผลิตที่อนุมัติแล้ว |
| 3 | ไม่เหลือบันทึกผลผลิตที่ยังรออนุมัติ |
| 4 | บันทึกที่อนุมัติแล้ว **ทุกแถว** มีผลตรวจ in-process ที่ **ผ่าน + หัวหน้า QC อนุมัติ** ผูกอยู่ |

![เช็กลิสต์ด่านส่งตรวจ QC ในการ์ดดำเนินการ — บอกว่ายังขาดอะไร ปุ่มส่งตรวจถูกปิดไว้จนกว่าจะครบ](manual-img/44-qc-gate.png)

✅ สถานะเปลี่ยนเป็น **"QC"** · ฝ่าย QC ได้แจ้งเตือน 📥 "งานมาถึงคุณ"

### ② หัวหน้า QC ตัดสิน + ลงนาม

🔑 บัญชี **หัวหน้า QC** → เปิดงาน (หรือการ์ดในหน้า **ตรวจ QC / QA**) จะเห็น 2 ปุ่ม

| ปุ่ม | ผลลัพธ์ |
|---|---|
| **"QC ผ่าน → ส่ง QA"** | สถานะไป **QA** |
| **"QC ตีกลับ"** | กลับไป **กำลังผลิต** · ต้องระบุเหตุผลให้ฝ่ายผลิตแก้ |

🖱️ กดปุ่ม → ระบบเปิด **แผงลงนาม** ✍️ พิมพ์ **รหัสผ่านบัญชีของคุณ** → 🖱️ **"ยืนยันลงนาม"**

![แผงลงนาม — ยืนยันด้วยรหัสผ่านบัญชีของตัวเองก่อนตัดสินคุณภาพ](manual-img/45-esign.png)

> 🔒 **นี่คือลายเซ็นอิเล็กทรอนิกส์ตาม GMP** — ระบบเก็บว่าใครลงนาม เมื่อไร ตัดสินว่าอะไร ลบไม่ได้
> **ผู้บริหารลงนามขั้นนี้แทนไม่ได้** ต้องเป็นหัวหน้า QC ตัวจริง · พนักงาน QC ไม่เห็นปุ่มนี้

## C11 · QA เก็บตัวอย่าง (ตรวจ Finished product) ✅ *(QA บันทึก · หัวหน้า QA อนุมัติ)*

🔑 บัญชี **QA** · การ์ด **"จุดเก็บตัวอย่าง (ตรวจ Finished product)"** → 🖱️ **"＋ บันทึกจุดเก็บตัวอย่าง"**

![ฟอร์มจุดเก็บตัวอย่าง — วันที่/เวลาที่เก็บ ผลตรวจ จำนวน และหมายเหตุ](manual-img/41-qa-sample-form.png)

✍️ **วันที่/เวลาที่เก็บ** (มีปุ่ม **"ตอนนี้"** ให้กดใส่เวลาปัจจุบัน) · **ผลตรวจ** (ผ่าน / ไม่ผ่าน) ·
**จำนวน** + หน่วย (เม็ด / g) · หมายเหตุ

![รายการจุดเก็บตัวอย่างที่บันทึกไว้](manual-img/36-qa-sample.png)

🔑 แล้ว **หัวหน้า QA** กด **"อนุมัติ"** / **"ไม่อนุมัติ"** (หัวหน้า QA ได้แจ้งเตือนเมื่อมีรายการใหม่ · ผู้บริหารอนุมัติแทนไม่ได้)

> ⚠️ **ผลตรวจ "ไม่ผ่าน" จะเปิด Incident Case ให้อัตโนมัติ** เหมือนกับ in-process
> · แก้รายการใช้กติกาเดียวกับ C8 · **ลบได้เฉพาะหัวหน้า QA** และต้องระบุเหตุผล (เก็บลงประวัติ)

> 🔒 **มีจุดเก็บตัวอย่างที่ยังรออนุมัติ หรือคำขอแก้ไขค้าง = ปล่อยผ่าน FG (C13) ไม่ได้**

## C12 · Incident Case (เหตุผิดปกติ) ⚠️ *(ทุกฝ่ายเปิดได้ · QA ตัดสิน)*

### เปิดเคส — ใครก็ได้ที่ล็อกอิน

🖱️ การ์ด **"⚠️ Incident Case / เหตุผิดปกติ"** → **"＋ เปิด Incident Case"**

![ฟอร์มเปิด Incident Case — หัวข้อ ประเภท ความรุนแรง และรายละเอียด](manual-img/42-incident-form.png)

✍️ **หัวข้อ** (เช่น `เครื่องตอกค้างระหว่างผลิต`) · **ประเภท** · **ความรุนแรง** · **รายละเอียด**

**ประเภทเหตุผิดปกติ 6 แบบ:** ผลตรวจระหว่างผลิตไม่ผ่าน · ตรวจ Finished product ไม่ผ่าน ·
เครื่องจักร/อุปกรณ์ · วัตถุดิบ/บรรจุภัณฑ์ · กระบวนการผลิต · อื่นๆ

**ความรุนแรง 3 ระดับ:** เล็กน้อย · ปานกลาง · ร้ายแรง

### เคสเดินผ่าน 5 สถานะ

```
เปิดเคส ──► รอ QA ตรวจสอบ ──► ส่งแผนกแก้ไข ──► รอ QA อนุมัติ ──► ปิดแล้ว
                  (QA)          (แผนกที่รับผิดชอบ)      (QA)
                                       ▲                  │
                                       └──────────────────┘
                                         QA ไม่ผ่าน — ส่งกลับให้แก้ใหม่
```

![Incident Case บนหน้ารายละเอียดงาน — สถานะ ความรุนแรง และหมายเหตุแยกรายฝ่าย](manual-img/37-incident.png)

| ขั้น | ใครทำ | ทำอะไร |
|---|---|---|
| 1. เปิดเคส | ทุกคน | หรือระบบเปิดเองเมื่อผลตรวจไม่ผ่าน |
| 2. **QA ตรวจสอบ** | QA | 🖱️ **"🔎 QA ตรวจสอบเคสนี้"** → เลือก **ประเภทเอกสาร DEV / OOS / NC** · ใส่ **เลขที่เอกสาร** · เลือก **แผนกที่รับผิดชอบ (เลือกได้หลายแผนก)** |
| 3. **แผนกแก้ไข** | แผนกที่ถูกมอบหมาย | กรอก **"การแก้ไขเบื้องต้น"** (บังคับ) แล้ว 🖱️ **"ส่งผลแก้ไขให้ QA"** |
| 4. **QA อนุมัติ** | QA | ผ่าน → ปิดเคส · ไม่ผ่าน → 🖱️ **"↩️ ไม่ผ่าน — ส่งกลับให้แผนกแก้ไข"** |
| 5. ปิดแล้ว / ยกเลิก | QA | ยกเลิกต้องระบุเหตุผล |

![Incident Case ในมุมมองของ QA — ขั้นตรวจสอบและมอบหมายแผนก](manual-img/43-incident-detail.png)

> 💡 **ทุกฝ่ายเพิ่มหมายเหตุของตัวเองได้** ผ่าน **"＋ เพิ่มหมายเหตุ"** — หมายเหตุมีป้ายสีบอกฝ่าย
> และ **ไม่ทับของฝ่ายอื่น**

> 💡 ผลตรวจที่ "ไม่ผ่าน" แล้วเคส Incident ปิดเรียบร้อย หน้างานและ eBR จะแสดงผลเป็น **"ผ่าน"** (ค่าเดิมยังอยู่ใน Audit)

> 🔒 **ด่านสำคัญ: มีเคสที่ยังไม่ปิด = ปล่อยผ่านไป FG ไม่ได้**
> ("ปิดแล้ว" และ "ยกเลิก" ถือว่าจบ · สถานะอื่นถือว่ายังค้าง)

## C13 · QA ปล่อยผ่าน ✅ *(หัวหน้า QA)*

🔑 บัญชี **หัวหน้า QA** → การ์ด **"ดำเนินการ"** (หรือการ์ดในหน้า **ตรวจ QC / QA**)

![ปุ่มตัดสินของ QA — QA ปล่อยผ่าน ส่ง FG และ QA ตีกลับ](manual-img/46-qa-decision.png)

| ปุ่ม | ผลลัพธ์ |
|---|---|
| **"QA ปล่อยผ่าน → FG"** | สถานะไป **FG (เข้าคลัง)** |
| **"QA ตีกลับ"** | กลับไป **กำลังผลิต** — **พนักงาน QA กดได้** |

🖱️ กด → ✍️ ใส่รหัสผ่าน → 🖱️ **"ยืนยันลงนาม"** (เหมือน C10)

> 🔒 **ปล่อยผ่าน = หัวหน้า QA เท่านั้น** — พนักงาน QA เห็นแค่ปุ่มตีกลับ · ผู้บริหารลงนามแทนไม่ได้

> ⚠️ **กดไม่ผ่านถ้ายังมี Incident Case ค้าง · จุดเก็บตัวอย่างรออนุมัติ · หรือคำขอแก้ไขค้าง** — ต้องเคลียร์ก่อน

## C14 · รับสินค้าเข้าคลัง (FG) = ปิดงาน 📦 *(คลังสินค้า)*

🔑 บัญชี **คลังสินค้า** · 📍 **เมนูซ้าย → คลัง / FG** → 🖱️ **"รับเข้าคลัง"** ที่งานนั้น

✍️ **จำนวนรับเข้า** (ต้องมากกว่า 0) · **หน่วย** (เม็ด / กล่อง / แผง) · **ตำแหน่งจัดเก็บ** (เช่น `ชั้น A-01`) ·
**ล็อต** · หมายเหตุ

![หน้าคลัง / FG — การ์ดสรุปและรายการที่รับเข้าแล้ว](manual-img/82-warehouse.png)

> 💡 **จ่ายสินค้าออกจากคลัง** — หน้าเดียวกัน กด **"📤 จ่ายออก"** ที่รายการ ใส่ **จำนวน** (จ่ายเกินคงเหลือไม่ได้) · **วันที่** · **เลขที่เอกสาร** · **ส่งให้ (ลูกค้า)** ·
> คงคลัง = รับเข้า − จ่ายออก · เลือก **เดือน** ด้านบนเพื่อดูความเคลื่อนไหวของเดือนนั้น · ลบใบจ่ายออกได้ (ต้องระบุเหตุผล · ยอดกลับเข้าคงคลัง)

## D1 · eBR — แฟ้มบันทึกการผลิต 📄 *(ทุกฝ่าย)*

หัว/ท้ายกระดาษทุกหน้า · **เลขหน้า "หน้า X / Y"** · ช่องลงนามท้ายเล่ม 3 ช่อง (ผู้จัดทำ · QC · QA — ลงนามในระบบแล้วเติมชื่อ/เวลาให้เอง)

## E1 · กล่องแจ้งเตือน 🔔 *(ทุกฝ่าย)*

📍 **เมนูซ้าย → 🔔 แจ้งเตือน** — ตัวเลขวงกลมแดงคือจำนวนที่ยังไม่อ่าน

![กล่องแจ้งเตือน — ชิปตัวกรองตามชนิด และรายการแจ้งเตือนพร้อมลิงก์ไปที่งาน](manual-img/72-inbox-full.png)

**แจ้งเตือนมี 17 ชนิด** เรียงจาก "ต้องลงมือทำ" ไป "รับทราบ"

| ไอคอน | ชนิด | เกิดเมื่อ | ส่งถึงใคร |
|:---:|---|---|---|
| ⏳ | **รออนุมัติ** | มีของรอหัวหน้าพิจารณา (Line Clearance · in-process · บันทึกผลผลิต · จุดเก็บตัวอย่าง) | หัวหน้าฝ่ายนั้น |
| ✏️ | **คำขอแก้ไข** | มีคนยื่นขอแก้ข้อมูลย้อนหลัง | ผู้อนุมัติตามชนิดคำขอ |
| ↩️ | **งานถูกตีกลับ** | QC หรือ QA ตีกลับ | ฝ่ายผลิต |
| ⚠️ | **Incident Case** | เปิด/อัปเดตเคส | ฝ่ายที่เกี่ยวข้อง |
| 🧾 | **ขอเบิกวัตถุดิบ** | ฝ่ายผลิตเพิ่มรายการเบิก | ฝ่ายคลัง |
| 🔬 | **รอตรวจ In-process** | มีบันทึกผลผลิตใหม่ | **พนักงาน QC รายคน** (ไม่ส่งหัวหน้า/ผู้บริหาร) |
| 🛠️ | **เครื่องถึงกำหนด** | เครื่องใกล้/เลยกำหนดซ่อมหรือสอบเทียบใน 7 วัน (เช็กทุกเช้า) | ฝ่ายวิศวกรรม |
| 📋 | **ข้อมูลไม่ครบ** | บันทึกผลผลิตขาดข้อมูล | ฝ่ายผลิต |
| ⏰ | **เกินกำหนด** | งานเลยแผนเสร็จแล้ว | ฝ่ายผลิต · ผู้บริหาร |
| 🐢 | **ค้างนาน** | งานไม่ขยับเกิน 3 วัน | ฝ่ายผลิต · ผู้บริหาร |
| 📥 | **งานมาถึงคุณ** | งานเดินมาถึงสถานะของฝ่ายคุณ | ฝ่ายปลายทาง |
| 🏭 | **งานเข้าสถานี** | บันทึกผลผลิตเข้าสถานีใหม่ / พร้อมเข้าสถานีแพ็ค | ฝ่ายที่เกี่ยวข้อง |
| 🆕 | **งานใหม่** | มีคนสร้างงานผลิต | ฝ่ายวางแผน (ไม่แจ้งคนสร้างเอง) |
| 🧪 | **ผลิตภัณฑ์ใหม่** | เพิ่มผลิตภัณฑ์ในทะเบียน | ฝ่ายผลิต (ให้ไปตั้งขั้นตอนการผลิต) |
| 📅 | **แผนเปลี่ยน** | เลื่อนแผน หรือ **ยกเลิกงาน** | ฝ่ายวางแผน |
| ✅ | **ผลการอนุมัติ** | หัวหน้าตัดสินแล้ว | **ผู้ยื่นคนเดียว** |
| 📝 | **ผลคำขอแก้ไข** | คำขอถูกอนุมัติ/ปฏิเสธ | **ผู้ยื่นคนเดียว** |

**สิ่งที่กดได้ในหน้านี้**

- 🖱️ **ชิปด้านบน** — กรอง ทั้งหมด / ยังไม่อ่าน / รายชนิด
- 🖱️ **"ทำเครื่องหมายอ่านทั้งหมด"** มุมขวาบน
- 🖱️ **"ไปที่งาน XXXXX →"** ในแต่ละใบ — **พาไปถึงขั้นตอน/รายการที่เกี่ยวข้องตรง ๆ** · **"อ่านแล้ว"** เพื่อเอาออกจากตัวนับ
- 🖱️ **ลบแจ้งเตือน** — ติ๊กรายใบ (หรือ "เลือกทั้งหมด") แล้วกดลบ · ลบ = **ซ่อนเฉพาะของคุณ** เพื่อนร่วมฝ่ายยังเห็นใบเดิม
- 🖱️ **"โหลดเพิ่ม"** ล่างสุด (ครั้งละ 30 · สูงสุด 200)

> 🔑 **แต่ละคนเห็นไม่เท่ากัน** — ใบส่วนใหญ่จ่าหน้าถึง "ฝ่าย" · บางใบจ่าหน้าถึง **ตัวบุคคล**
> (ผลการอนุมัติ · ผลคำขอแก้ไข) ซึ่ง **แม้แต่ผู้บริหารก็ไม่เห็น** — ตั้งใจให้เป็นความเป็นส่วนตัวของผู้ยื่น
> · **ผู้บริหารเห็นแจ้งเตือนของทุกฝ่าย** ยกเว้นใบรายบุคคล

> ⚠️ **⏰ เกินกำหนด และ 🐢 ค้างนาน เป็นใบที่ระบบคำนวณสด** — มีป้าย "อัตโนมัติ"
> **ไม่นับในตัวเลขสีแดง** และกด "อ่านแล้ว" ไม่ได้ · จะหายเองเมื่องานขยับ

> 💡 **แจ้งเตือนเก่ากว่า 7 วันถูกล้างให้อัตโนมัติ** (ตี 2 ทุกคืน) · ใบ "อัตโนมัติ" ติ๊กลบไม่ได้

## E2 · ขอแก้ไขย้อนหลัง (Amendment) ✏️

ข้อมูลที่บันทึกแล้วแก้เองไม่ได้ทั้งหมด — บางอย่างต้องขออนุมัติก่อน ตามหลัก GMP ที่ห้ามแก้บันทึกเงียบ ๆ

### ① ยื่นคำขอ

🔑 บัญชีคนที่บันทึกไว้ → 🖱️ ปุ่ม **"✏️ ขอแก้ไข"** ที่แถวนั้น (บันทึกผลผลิต · ผลตรวจ in-process · จุดเก็บตัวอย่าง)

> 💡 **ใช้กับรายการที่ "อนุมัติแล้ว" เท่านั้น** — รายการที่ยังรออนุมัติหรือถูกตีกลับ ผู้บันทึกแก้ตรงได้เลย (ดูตารางใน C8)

![กล่องขอแก้ไขย้อนหลัง — แก้ค่าแล้วระบุเหตุผลเพื่อให้ผู้อนุมัติพิจารณา](manual-img/48-edit-request.png)

✍️ แก้ค่าที่ต้องการ + **ระบุเหตุผล** (บังคับ) → 🖱️ **"ส่งคำขอแก้ไข"**

> ⚠️ **ถ้าไม่ได้แก้ค่าอะไรเลย ระบบจะไม่ให้ส่ง** — ขึ้นว่า "ยังไม่มีการแก้ไข (ค่ายังเหมือนเดิม)"

### ② ผู้มีสิทธิ์อนุมัติ

📍 **เมนูซ้าย → คำขอแก้ไข (Amendment)** — มีตัวเลขสีเหลืองบอกจำนวนที่ค้าง

![หน้าอนุมัติคำขอแก้ไข — เทียบค่าเดิมกับค่าใหม่ทีละช่อง](manual-img/73-edit-review.png)

หน้านี้แสดง **ค่าเดิม → ค่าใหม่** ทีละช่อง พร้อมเหตุผลของผู้ยื่น
🖱️ **"✅ อนุมัติ + แก้ให้"** (ระบบแก้ข้อมูลให้เลย) หรือ **ปฏิเสธ** (ต้องใส่หมายเหตุ)

| ชนิดคำขอ | ใครอนุมัติได้ |
|---|---|
| **บันทึกผลผลิต** | ผู้บริหาร · **หัวหน้าฝ่ายผลิต** |
| **ผลตรวจ QC ระหว่างผลิต** | ผู้บริหาร · **หัวหน้า QC** |
| **จุดเก็บตัวอย่าง (QA)** | **หัวหน้า QA เท่านั้น** (ผู้บริหารอนุมัติแทนไม่ได้) |

> 🔒 **มีคำขอแก้ไขค้างอยู่ = ปล่อยผ่าน FG ไม่ได้** จนกว่าจะพิจารณาเสร็จ · งานที่ถูกยกเลิก คำขอที่ค้างถูกปิดให้อัตโนมัติ

✅ ผลการพิจารณาถูกส่งกลับ **ถึงผู้ยื่นคนเดียว** และการแก้ไขทั้งหมดถูกบันทึกลง **ประวัติ / Audit**
